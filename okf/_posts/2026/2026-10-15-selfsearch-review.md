## 논문 개요와 전체 구조

에이전트가 코드를 수정할 수 있다면 자신을 실행하는 도구와 지침도 바꿀 수 있습니다. 문제는 어떤 수정이 좋은지 알아내는 비용입니다. 후보를 만들 때마다 실제 문제를 풀게 하고 점수를 확인하면, 평가 문제 수와 반복 횟수에 따라 탐색 비용이 누적됩니다. **SelfSearch는 자기 수정 과정에서 생긴 행동 기록을 다음 수정의 근거로 사용하고, 탐색 중에는 downstream 벤치마크의 문제나 정답 보상을 제공하지 않는 방법**입니다. 여기서 downstream은 개선된 에이전트가 나중에 수행하는 소프트웨어 수정·터미널 작업을 뜻합니다. [초록·1절](https://arxiv.org/html/2609.37968v2#S1)

하네스(harness)는 모델 주변의 도구, 지침, 실행 절차를 구성하는 소프트웨어 층입니다. 이 연구는 모델 가중치를 학습하지 않고 하네스를 바꿉니다. 긴 실행 기록이 잘려 필요한 내용을 읽지 못했다면 검색 도구를 만들고, 검색 결과를 줄이는 과정에서 일치 구간이 사라졌다면 출력 방식을 고치는 식입니다. 이렇게 발전한 도구와 수정 경험이 다음 세대로 함께 전달됩니다. **reward-free는 탐색에 downstream 평가 보상을 쓰지 않는다는 뜻이며, 도구의 오류·로컬 검사 결과까지 없애거나 최종 성능 평가를 생략한다는 뜻은 아닙니다.**

## 핵심 기여와 혁신성

첫째, **자기 수정의 산출물을 코드와 경험으로 나눠 보존합니다.** 기존 탐색의 주요 피드백은 후보가 과제를 얼마나 잘 풀었는지입니다. SelfSearch는 후보를 만드는 동안 어떤 파일을 읽었고, 무엇을 잘못 관찰했으며, 어떤 편집·검사를 했는지를 다음 수정의 입력으로 삼습니다. 작업을 풀어야만 개선의 근거를 얻을 수 있다는 제약을 완화하려는 접근입니다. [1–2절](https://arxiv.org/html/2609.37968v2#S2)

둘째, **개선된 에이전트가 다음 개선도 수행합니다.** 수정 대상만 바뀌고 수정하는 프로그램은 고정되는 구조와 달리, 같은 에이전트 구현이 과제 수행과 자기 수정을 맡습니다. 도구가 좋아지면 다음 수정 과정에서도 이를 사용할 수 있습니다. 두 독립 계보는 서로의 코드를 자동으로 합치는 대신 이전 세대의 기록을 공유해 필요한 변경을 선택적으로 도입합니다.

셋째, **성능만이 아니라 비용과 전이를 함께 측정합니다.** 두 모델 계열과 세 벤치마크를 결합한 여섯 설정에서 최종 두 계보의 평균 성공률이 초기 에이전트보다 높았습니다. 다만 개별 계보는 모든 설정에서 개선되지 않았으며, 이 평균은 독립적인 전체 탐색 반복들의 평균도 아닙니다. 두 모델 계열 간 구현 전이와 도구 사용 분석은 개선이 어떤 실행 절차에 남았는지를 보여줍니다. [3–4절](https://arxiv.org/html/2609.37968v2#S3)

리뷰어 관점의 학습 가치는 **“최종 답의 정오”와 “행동 과정에서 드러난 소프트웨어 문제”를 다른 개선 신호로 다루는 방법**입니다. 에이전트의 기록 구조, 파일 편집 인터페이스, 출력 제한, 재사용 가능한 도구 설계를 함께 공부할 수 있습니다. 이 연구의 주 평가는 코딩과 터미널 과제이며 Robotics 연구가 아닙니다.

## 기술적 세부사항

### 무엇이 바뀌고 무엇이 고정되는가

초기 에이전트는 DGM의 코딩 에이전트를 바탕으로 shell 실행과 파일 편집을 제공하고, 일반 작업·코딩·자기 수정 지침이 담긴 policy library를 추가합니다. 에이전트 저장소의 지침·도구·작업 수준 orchestration은 수정할 수 있습니다. 반면 모델 호출과 도구 실행을 진행하는 런타임은 저장소 밖에 있으며 모델, 추론 강도, 출력 제한, 실행 예산을 관리합니다. 이전 수정 기록 역시 외부에서 읽기 전용으로 제공됩니다. 따라서 에이전트 코드가 바뀌어도 평가 조건과 기록 관리의 경계는 유지됩니다. [부록 A](https://arxiv.org/html/2609.37968v2#A1)

한 에피소드에서는 현재 에이전트가 자신의 편집 가능한 복사본을 수정합니다. **지금 실행 중인 에이전트는 그대로이고, 수정 결과가 다음 에피소드의 실행자가 됩니다.** 모델 가중치는 고정되어 있으므로 강화학습의 파라미터 업데이트 식이 아니라 구현을 바꾸는 절차입니다.

### 두 계보와 기록 공유

capability 계보는 부족한 능력을 해결할 재사용 도구·절차에, adaptive 계보는 실패나 반대 증거를 만났을 때 접근을 수정하는 능력에 초점을 둡니다. 방향은 정성적인 지침이며 점수 함수가 아닙니다. 각 모델 설정에서 두 계보를 10세대 진행하고, 마지막 세대의 두 에이전트를 평가합니다. 탐색 중 성능이 가장 좋았던 체크포인트를 골라낸 결과가 아닙니다. [2절·Algorithm 1](https://arxiv.org/html/2609.37968v2#alg1)

### 평가 조건과 지표의 단위

| 구분 | GPT 설정 | DeepSeek 설정 |
|---|---|---|
| 자기 수정 모델 | `gpt-5.6-sol` | `deepseek-v4-pro-0813` |
| downstream 실행 모델 | `gpt-5.6-luna` | `deepseek-v4-flash-0731` |
| 기본 추론 강도·temperature | medium·1 | medium·1 |
| 탐색 중 호출당 출력 상한 | 8,192 tokens | 16,384 tokens |
| downstream 호출당 출력 상한 | 16,384 tokens | 16,384 tokens |

탐색 에피소드 하나의 상한은 모델 호출 513회, 도구 단계 512회, 실행 4시간이며 네트워크가 차단된 컨테이너를 사용합니다. 과제는 SWE-bench Verified 120개, SWE-bench Multilingual 60개, Terminal-Bench 2.1 전체 89개입니다. 성공률은 해결된 과제 비율이며 평균 실행 비용은 **실패한 과제까지 포함한 과제당 모델 비용**입니다. 뒤의 공통 성공 비용 지표는 각 에이전트 쌍이 모두 성공한 과제만 비교하므로 분모가 다릅니다. 비용식은 원문 순서대로 부록 C.4 리뷰에서 전개합니다. [3.1절·부록 C](https://arxiv.org/html/2609.37968v2#A3)

## 챕터별 상세 리뷰

### 📖 **Chapter 1: Introduction**

**챕터의 위치와 역할**: 연구 동기에서 시작해 자기 수정 경험이 왜 별도의 개선 근거가 될 수 있는지 설명합니다. 문제를 “스스로 코드를 바꿀 수 있는가”보다 “그 과정에서 무엇을 배울 수 있는가”에 둡니다.

**저자의 서술 순서를 따른 상세 내용:**

**1. 메타인지에서 출발합니다.** 사람은 능력의 한계를 파악하고 이를 고치는 동안, 문제 자체뿐 아니라 실패에 대응하고 학습 방법을 바꾸는 경험도 얻습니다. 저자들은 코딩 가능한 LLM 에이전트도 자신을 구성하는 구현을 조사·수정하면서 비슷한 경험을 얻을 수 있는지 질문합니다. 이는 인간의 메타인지와 동일한 능력을 증명한다는 주장이 아니라 연구를 유도하는 비유입니다.

**2. 기존 평가 중심 개선의 비용을 설명합니다.** 후보 에이전트가 실제 작업을 수행한 결과는 유용하지만, 매 후보를 개발 집합에서 실행하면 평가 수에 따라 반복 비용이 늘어납니다. 또한 개선 방향이 평가한 과제 분포와 연결됩니다. SelfSearch가 줄이려는 것은 이 후보 생성 과정의 downstream 평가 의존성입니다.

**3. 수정 과정 자체를 경험으로 재정의합니다.** 수정은 새로운 코드뿐 아니라 한계를 발견하고 변경을 만들며 검증한 기록도 남깁니다. 긴 기록을 읽기 어려웠다는 경험은 검색·조회 도구를, 잘못된 편집은 수정 전 관련 코드를 확인하는 절차를 유도할 수 있습니다. 다음 세대는 개선된 구현과 이전 경험을 함께 받습니다.

*Figure 1, PDF 2쪽. 같은 버전 PDF의 그림 영역을 크롭했으며 번역·수치 변경은 없습니다. 쌓인 상자는 병렬 계보를 나타내고, 구현과 기록은 서로 다른 산출물로 다음 세대에 전달됩니다. [원문 그림](https://arxiv.org/html/2609.37968v2#S1.F1)*

**4. 보상 부재의 범위와 가설을 명확히 합니다.** 탐색에는 downstream 과제·평가 결과를 제공하지 않습니다. 그러나 파일 조회, 도구 오류, 로컬 검사 결과는 사용할 수 있습니다. 저자의 가설은 생소한 코드 조사, 오류 진단, 수정 구현, 효과 확인이 자기 수정과 downstream 작업 모두에 필요하다는 것입니다. 따라서 자기 수정을 개선하는 도구가 실제 과제에도 도움이 될 수 있습니다.

**5. 결과와 기여를 예고합니다.** 두 모델 설정·세 벤치마크에서 최종 population mean이 개선되고, 일부 개별 에이전트의 성공률과 효율이 좋아졌으며 구현이 모델 사이에 전이됩니다. 초록의 최대 11.2 percentage points와 82.0%는 서로 다른 비교입니다. 전자는 기본 조건의 초기 에이전트 대비 개별 개선이고, 후자는 다른 하네스와 맞춘 확대 실행 조건의 결과입니다.

**챕터의 핵심 기여**: 자기 수정의 행동 기록을 다음 후보 생성의 근거로 사용할 수 있다는 연구 질문과 검증 가능한 범위를 설정합니다. **다음 챕터로의 연결**: 2절은 이 경험을 어떤 자료구조와 세대 전환으로 전달하는지 정의합니다. [1절](https://arxiv.org/html/2609.37968v2#S1)

### 📖 **Chapter 2: SelfSearch**

**챕터의 위치와 역할**: 한 번의 수정, 계보 간 정보 공유, 고정된 실행 환경을 순서대로 정의하는 방법론의 중심입니다.

**저자의 서술 순서를 따른 상세 내용:**

**1. Self-improvement episode — 실행자와 편집 대상을 구분합니다.** 초기 에이전트 $`B_0`$는 지침·도구·실행 로직이 담긴 저장소입니다. 에피소드 $`k`$에서 실행자 $`B_k`$는 자기 저장소의 편집 가능한 복사본과 이전 기록 $`\mathcal{E}_k`$를 받습니다. 이를 조사하고 변경·검증해 후속 구현을 만듭니다. 원문 식 (1)은 다음과 같습니다.

```math
(B_{k+1},e_k)=\mathrm{SelfImprove}(B_k;\mathcal{E}_k,d).
```

$`B_k`$는 현재 수정 작업을 수행하는 구현, $`B_{k+1}`$은 수정 결과, $`e_k`$는 이번 수정의 기록입니다. $`\mathcal{E}_k`$는 이전 에피소드 기록 모음이고 $`d`$는 어떤 종류의 개선을 탐색할지 정하는 정성적 지침입니다. 세미콜론은 입력 구현과 보조 입력을 구분합니다. `SelfImprove`는 특정 신경망 층이나 학습 손실이 아니라 기록 조사→수정→검사의 전체 절차입니다. 기록에는 추론, 도구 행동과 결과, 코드 변경이 포함됩니다. 다음 에피소드에서 후속 구현이 실행자가 되므로 도구의 변화가 자기 수정 방식에도 영향을 줍니다. [식 (1)](https://arxiv.org/html/2609.37968v2#S2.E1)

**2. Search across generations — 두 방향이 다른 종류의 문제를 조사합니다.** capability 방향은 비효율, 실패한 행동, 수행하기 어려운 연산에서 드러난 능력 부족을 찾아 재사용 도구·절차로 해결하도록 요청합니다. adaptive 방향은 행동 실패나 가정에 반하는 증거를 만났을 때 계획을 수정하는 방식에 초점을 둡니다. 방향 자체가 candidate의 성공률을 계산하거나 어느 쪽이 우수한지 채점하지 않습니다.

첫 세대에 읽을 경험을 마련하기 위해 초기 에이전트를 각 방향으로 한 번씩 실행합니다. 여기서 얻은 **기록은 보존하지만 수정된 구현은 버립니다.** 따라서 두 계보는 동일한 초기 구현에서 출발합니다. 이후 각 계보는 직전 세대의 두 기록을 모두 받지만 자기 구현을 따로 유지합니다. 다른 계보에서 나온 도구를 읽고 옮길 수 있으나 저장소 전체가 자동으로 합쳐지는 것은 아닙니다.

**3. Algorithm 1 — 공유하는 것은 기록이고 보관하는 것은 모든 후보입니다.** 계보 수 $`W`$, 세대 수 $`K`$에 대해 각 계보의 초기 구현을 동일하게 설정하고 archive를 초기화합니다. 매 세대의 수정 에피소드는 계보별로 병렬 실행합니다. 새 기록 묶음과 archive 갱신은 다음과 같습니다.

```math
\begin{aligned}
\mathcal{E}_{k+1}&=\{e_k^1,\ldots,e_k^W\},\\
\mathcal{C}&\leftarrow\mathcal{C}\cup\{B_{k+1}^1,\ldots,B_{k+1}^W\}.
\end{aligned}
```

위 첨자 $`w`$는 계보, $`\mathcal{C}`$는 생성된 에이전트 보관함입니다. $`\mathcal{E}_{k+1}`$는 모든 과거 기록의 누적 집합이 아니라 **직전 세대에서 나온 계보별 기록 묶음**입니다. 전체 후보 보존과 매 에피소드 입력으로 제공하는 기록의 범위를 혼동하지 않아야 합니다. 논문 실험은 두 계보·10세대이며 최종 세대의 각 계보를 보고합니다. [Algorithm 1](https://arxiv.org/html/2609.37968v2#alg1)

**4. Search environment — 수정 권한과 관찰의 경계를 고정합니다.** 탐색 중 downstream 벤치마크 과제와 점수는 보이지 않으며, 평가할 체크포인트를 고정한 뒤 별도로 평가합니다. 실행 루프는 편집 저장소 밖에 두어 변화한 구현을 일정한 방식으로 실행하고 기록합니다. 모델, reasoning effort, 출력·실행 예산도 런타임이 관리합니다. 에이전트는 공통 인터페이스를 호출하면서 주변 도구·지침·orchestration을 바꿀 수 있습니다.

**챕터의 핵심 기여**: 구현의 계승과 경험의 공유를 분리하고, 후보 생성에 downstream 보상을 사용하지 않는 탐색 절차를 정의합니다. **다음 챕터로의 연결**: 3절은 이 절차로 만든 마지막 세대 구현을 실제 문제에서 평가합니다. [2절](https://arxiv.org/html/2609.37968v2#S2)

### 📖 **Chapter 3: Experiments**

**챕터의 위치와 역할**: 기본 성능·실행 비용부터 평가 기반 탐색, 모델 전이, 다른 하네스 비교로 검증 범위를 넓힙니다. 비교별 과제 수와 추론 조건이 바뀌므로 이를 따로 읽어야 합니다.

**저자의 서술 순서를 따른 상세 내용:**

#### 3.1 Experimental Setup

**Agents and models.** GPT 설정은 Sol로 자기 수정하고 Luna로 실제 작업을 수행하며, DeepSeek 설정은 Pro로 수정하고 Flash로 실행합니다. 동일 설정 안의 초기·개선 에이전트는 downstream 모델과 실행 제한이 같고 구현만 다릅니다. 자기 수정에 더 강한 모델을 사용했다는 사실과, 최종 실행 모델 가중치는 학습하지 않았다는 사실이 함께 성립합니다.

**Search configuration.** 두 계보를 10세대 진행한 뒤 마지막 capability·adaptive 구현을 각각 평가합니다. 모든 체크포인트는 저장하지만 downstream 점수로 최종 후보를 선택하지 않습니다. 아래에서 population mean은 이 두 계보 성공률의 산술평균이며, 여러 독립 탐색의 평균 또는 두 에이전트를 합쳐 문제를 푼 ensemble 점수가 아닙니다.

**Downstream evaluation.** SWE-bench Verified 120개는 저장소 이슈 수정, Multilingual 60개는 여덟 언어의 코드 수정, Terminal-Bench 2.1의 89개는 터미널 환경의 과제입니다. 세 벤치마크를 모두 동일한 “정확도 데이터셋”으로 취급하기보다 파일·도구·검증을 사용하는 수행 과제로 이해해야 합니다. 각 벤치마크의 grader가 성공 여부를 결정합니다.

**Cost metrics와 Baselines.** 과제당 비용은 시도한 모든 과제의 모델 비용을 나누며 탐색 비용은 제외합니다. 초기 에이전트와 두 개선 구현을 비교하고, 별도로 개발 집합 점수로 개선하는 linear·archive search와 두 메커니즘 제거 실험을 둡니다. [3.1절](https://arxiv.org/html/2609.37968v2#S3.SS1)

#### 3.4 Cross-Model Transfer

다른 모델로 실행할 때 추가 탐색과 코드 변경은 하지 않습니다. GPT Sol이 만든 두 구현을 DeepSeek Flash로 실행하면 Verified 성공률은 초기 81.7%에서 capability 83.3%, adaptive 85.0%가 됩니다. 반대로 DeepSeek Pro가 만든 구현을 GPT Luna로 실행하면 초기 75.0%에서 79.2%, 76.7%가 됩니다. [Table 3](https://arxiv.org/html/2609.37968v2#S3.T3)

이는 발견한 파일 조회·편집·도구 절차가 수정에 사용한 모델 계열에만 종속되지 않았다는 근거입니다. 평가 범위는 두 실행 모델과 Verified 집합이며 모든 모델·과제로의 보편적 이식을 확인한 것은 아닙니다.

#### 3.5 Comparison with Other Harnesses

DeepSeek Pro로 탐색한 capability 구현을 DeepSeek Flash로 실행해 공개된 9개 하네스 비교 조건에 맞춥니다. 여기서는 **xhigh 추론, 과제별 지정 시간 제한, 도구 단계 100,000회·모델 호출 100,001회**를 사용합니다. 기본 Table 1의 medium 결과 73.0%와 조건이 다릅니다.

이 설정에서는 89개 중 73개, 82.0%를 해결해 공개 비교의 최고 점수인 Codex와 동률입니다. 두 하네스가 모두 푼 과제는 66개이고 각각 7개씩은 상대가 풀지 못한 과제입니다. 따라서 총점 동률을 같은 문제 해결 능력 또는 동일한 오류 패턴으로 해석하지 않습니다. USD 4.03은 그 하네스를 만든 탐색 비용이며 **89개 평가 실행을 모두 포함한 총비용이 아닙니다.** 다른 하네스 수치의 근거는 논문이 인용한 공개 비교이며, 이 리뷰가 해당 비교를 독립 재실행한 결과는 아닙니다. [3.5절·부록 D.3](https://arxiv.org/html/2609.37968v2#A4.SS3)

**챕터의 핵심 기여**: 최종 두 계보의 성능·효율, 평가 기반 탐색 대비 비용, 모델 전이와 별도 확대 설정의 하네스 비교를 제시합니다. **다음 챕터로의 연결**: 4절은 개선이 기록과 실행자 진화 중 어디서 비롯되는지, 실제로 무엇이 바뀌었는지 분석합니다.

#### 4.1 Episode Records and the Evolving Improver

#### 4.2 How Improvements Develop

원문은 먼저 GPT의 10세대 변화(Table 5)를 제시합니다. 두 계보는 다른 순서로 비슷한 인터페이스를 도입하고, 후반부에는 기록을 더 잘 조사하는 도구로 발전합니다.

| 세대 | capability 계보 | adaptive 계보 |
|---|---|---|
| 1 | 정확한 문자열 치환 | 계획 수정·실패 복구 |
| 2 | 행 범위 파일 조회 | 정확한 문자열 치환 |
| 3 | 계획 수정·실패 복구 | 행 범위 파일 조회 |

| 5 | 시작 시 일반 지침 로드 | 문자 범위 파일 조회 |
| 6 | 출력 제한이 있는 텍스트 검색 | 구조화된 trajectory reader |
| 7 | 구조화된 trajectory reader | 출력 제한이 있는 텍스트 검색 |

*Table 5의 순서와 계보를 보존해 번역했습니다. 같은 항목의 반복은 다른 계보의 변경을 가져온 경우를 포함합니다. [원문 표](https://arxiv.org/html/2609.37968v2#S4.T5)*

**GPT inspection tools.** 6세대 capability가 검색 도구를, adaptive가 기록 reader를 만듭니다. 7세대에는 상대의 기록에서 이 도구를 확인해 도입합니다. adaptive는 reader로 capability의 기록을 읽고 검색 구현과 테스트를 가져옵니다. 개별 excerpt를 짧게 제한해도 여러 조각을 합치면 전체 응답이 커진다는 문제가 드러나 8세대에서 전체 출력 제한을 추가합니다. 이어 관련 이벤트 필터와 호출 인자·결과의 연결이 발전합니다.

이 흐름의 요점은 “기록을 제공하면 자동으로 좋아진다”가 아닙니다. 기록을 소비하는 과정에서 생긴 관찰 문제를 수정하고, 그 수정 도구를 다음 세대가 다시 사용하면서 더 정교하게 만든다는 구체적인 연쇄입니다.

**DeepSeek search-output repair.** 5세대 adaptive는 긴 검색 출력의 앞뒤만 남겼는데, 일치 텍스트가 가운데 있으면 사라질 수 있었습니다. 6세대 capability가 이 기록을 읽고 일치 지점을 중심으로 excerpt를 보여주도록 고칩니다. 7세대 adaptive는 실패를 재현하고 상대의 수정을 가져와 일치 텍스트가 보이는지 검사합니다. 뒤에서는 파일 조회·수정 시 tab과 줄바꿈을 보존하는 변경도 이루어집니다. 이는 논문이 실제 기록에서 분석한 실패·복구 사례입니다. [4.2절·부록 E.1](https://arxiv.org/html/2609.37968v2#S4.SS2)

### 📖 **Chapter 6: Discussion**

**챕터의 위치와 역할**: 관찰 결과의 의미와 저자가 명시한 후속 검증 방향을 제시합니다. 별도의 Limitations 절은 없으며 여기의 논의를 임의의 한계 목록으로 확장하지 않습니다.

**저자의 서술 순서를 따른 상세 내용:**

**1. 후보 생성과 평가 비용을 분리합니다.** downstream 평가는 유용하지만 과제 범위와 반복 수가 늘면 비용이 커집니다. 본 실험은 자기 수정 경험으로도 경쟁력 있는 후보를 생성할 수 있음을 보였습니다. 평가·선택 비용이 사라진 것이 아니라 생성과 별도 단계로 남습니다. 사후 결과가 좋은 후보를 배포할지 결정하려면 여전히 해당 목적에 맞는 평가가 필요하다는 구조입니다.

**2. 자기 수정이 드러내는 도구·절차 문제를 설명합니다.** 기록은 코드 조사, 편집, 검사에서 겪은 어려움을 다음 세대가 조사할 구체적인 문제로 제공합니다. 일부 도구는 downstream에 재사용되고 trajectory reader처럼 추가 자기 수정을 돕는 도구도 있습니다. 저자들은 이런 경험이 평가 없는 수정의 근거가 된다고 해석합니다. 동시에 **독립적인 여러 탐색에서 개선이 얼마나 일관되게 나타나는지 추가 연구가 필요하다**고 명시합니다. 이는 이 리뷰가 새로 추측한 실패가 아니라 원문의 후속 검증 과제입니다.

**3. 평가 기반 선택과의 결합을 제안합니다.** 하나의 평가 기반 수정 단계를 SelfSearch 여러 세대로 확장한 뒤 결과 후보를 평가·보존할 수 있다는 아이디어를 제시합니다. 저자는 같은 총 탐색 예산에서 이 결합이 더 좋은 에이전트를 만드는지 검증할 것을 제안합니다. 현재 Table 2가 예산을 맞춘 결합 실험까지 수행했다는 뜻은 아닙니다.

**챕터의 핵심 기여**: reward-free 후보 생성과 평가 기반 선택을 상호 보완적인 역할로 위치시킵니다. **다음 챕터로의 연결**: 7절은 입증한 범위를 간결히 정리합니다. [6절](https://arxiv.org/html/2609.37968v2#S6)

#### C.4 Cost Metrics and Inference Pricing

원문은 과제 $`i`$에서 구현 $`B`$의 전체 모델 실행 비용을 $`c_i(B)`$, 성공 지시자를 $`s_i(B)\in\{0,1\}`$로 정의합니다. 평가 집합 $`\mathcal{T}`$의 평균 비용은 식 (2)입니다.

```math
\bar{c}(B)=\frac{1}{|\mathcal{T}|}\sum_{i\in\mathcal{T}}c_i(B).
```

$`|\mathcal{T}|`$는 시도한 과제 수이며 분자에는 성공과 실패의 비용이 모두 들어갑니다. 예를 들어 Multilingual의 분모는 60입니다. $`\bar{c}`$를 “성공 한 건을 얻는 데 필요한 비용”과 동일시하면 안 됩니다. 후자는 성공률까지 함께 반영하는 별도 계산이 필요하며 논문은 위 지표를 보고합니다. [식 (2)](https://arxiv.org/html/2609.37968v2#A3.E2)

초기 구현에 대한 평균 비용 절감률은 식 (3)입니다.

```math
R(B)=100\left(1-\frac{\bar{c}(B)}{\bar{c}(B_0)}\right).
```

$`B_0`$는 초기 구현입니다. 개선 구현의 평균 비용이 초기보다 작으면 양수, 크면 음수가 됩니다. 전체 과제 집합에서 계산하므로 에이전트마다 성공·실패한 과제 구성이 달라질 수 있습니다. [식 (3)](https://arxiv.org/html/2609.37968v2#A3.E3)

같은 과제를 모두 성공했을 때의 효율을 비교하기 위해 공통 성공 집합을 정의합니다.

```math
\mathcal{S}_B=\{i\in\mathcal{T}:s_i(B)=s_i(B_0)=1\}.
```

$`\mathcal{S}_B`$는 개선·초기 에이전트가 **모두** 해결한 과제만 담습니다. capability와 adaptive는 서로 다른 공통 성공 집합을 가질 수 있습니다. 식 (4)는 이 집합의 모델 비용 합으로 비교합니다.

```math
R_{\mathrm{shared}}(B)=100\left(1-\frac{\sum_{i\in\mathcal{S}_B}c_i(B)}{\sum_{i\in\mathcal{S}_B}c_i(B_0)}\right).
```

두 합은 동일한 과제 집합을 사용하므로 과제 난도가 다른 집합을 비교하는 효과를 줄입니다. 집합 크기가 양쪽에서 같아 평균 대신 합을 사용해도 비율은 같습니다. **38.5%는 이 식으로 계산한 DeepSeek adaptive의 Multilingual 공통 성공 39개 결과**입니다. 전체 60개의 평균 비용이 38.5% 줄었다거나 성공률이 38.5% 올랐다는 뜻이 아닙니다. 비용 지표들은 탐색 비용을 제외합니다. [식 (4)](https://arxiv.org/html/2609.37968v2#A3.E4)

논문 계산에 적용한 100만 tokens당 입력·cached input·출력 가격은 Luna USD 0.20·USD 0.02·USD 1.20, Flash USD 0.15·USD 0.003·USD 0.60입니다. 입력 가격은 uncached token에 적용합니다. 이는 논문 비용을 해석하기 위한 실험 가격이며 현재 서비스의 견적을 보장하는 안내가 아닙니다.

## 기술적 함의와 응용

**저자의 주장에 따른 함의**는 수정 경험과 downstream 평가가 다른 역할을 할 수 있다는 것입니다. 기록에서 발견한 관찰·편집 문제로 후보를 여러 번 개선하고, 별도 평가로 그 후보를 검증·선택할 수 있습니다. 평가가 없는 자기 수정도 유용할 수 있다는 결과가 평가의 폐기를 뜻하지는 않습니다. [6절](https://arxiv.org/html/2609.37968v2#S6)

**리뷰어 관점의 적용 해석**으로는 에이전트 운영 로그를 실패 문장 모음보다 넓게 설계할 가치가 있습니다. 호출 인자와 결과의 연결, 잘림 여부, 변경 전후 코드, 검사 결과가 있어야 도구 인터페이스의 문제를 구체적으로 재구성할 수 있습니다. SelfSearch의 실제 발전은 거대한 새 추론 알고리즘보다 정확한 치환, 행 범위 조회, 일치 구간을 보존하는 검색, tab·줄바꿈 유지처럼 작업의 근거를 잃지 않는 연산에 집중됐습니다. 이 관찰은 하네스 설계에서 기록의 가독성과 편집의 정확성을 함께 다뤄야 하는 이유를 보여줍니다.

또한 **개선 실행자, 편집 가능한 구현, 고정 런타임, 사후 평가를 구분하는 경계**를 공부할 수 있습니다. 같은 에이전트가 자기 수정과 실제 작업을 맡더라도 모델·자원 예산·기록 관리까지 모두 편집 대상으로 둘 필요는 없습니다. 여기의 일반적 설계 해석은 논문이 산업 배포 안정성이나 범용 업무 성능까지 검증했다는 주장이 아닙니다.

이 연구는 자기 수정 경험에서 재사용 가능한 도구를 만들고, 그런 도구가 다시 자기 수정과 실제 작업을 돕는 순환을 제시합니다. 원문의 다음 검증 방향은 독립 탐색에서의 일관성과 동일 총예산 아래 평가 기반 선택과의 결합입니다. **SelfSearch가 보여준 것은 정답 평가 없이도 후보를 개선할 경험을 얻는 방법이며, 그 후보의 실제 가치는 별도 평가 조건·성공 집합·비용 분모를 유지해 판단해야 합니다.**
