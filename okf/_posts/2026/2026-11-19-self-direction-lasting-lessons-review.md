## 논문 개요와 전체 구조

에이전트가 웹 검색을 반복하다 작업을 끝내지 못했다고 가정해 보겠습니다. 같은 세션에서 “이미 찾은 자료를 정리하고 다른 도구를 써 보라”고 알려 주면 다음 시도는 나아질 수 있습니다. 그러나 새 세션에서 같은 실수를 피하려면 그때의 교훈을 다시 전달해야 합니다. 이 논문은 실패한 실행을 돌아보고 만든 교정 예제를 작은 모델 어댑터에 학습해, 이후에도 꺼내 쓸 수 있게 하는 **Self-Direction**을 제안합니다. [원문 §1][s1]

여기서 교훈은 정답 문장을 저장한 메모와 다릅니다. 모델은 자신이 어떤 절차를 잘못 적용했는지 살펴보고, 관련 상황에 적용할 instruction–response 예제를 합성합니다. 그 예제로 저랭크 어댑터 하나를 학습하고 작업 설명을 검색 키로 등록합니다. 최초 실행은 항상 원래 모델로 하고, 실패했을 때만 저장한 어댑터를 찾거나 새로 학습합니다. 이 순서가 즉시 복구와 이후 재사용, 원래 능력 보존을 연결합니다. [§3.3][s33] · [부록 F][af]

## 핵심 기여와 혁신성

저자들이 다루는 문제는 현재 과제의 복구가 다음 과제의 학습으로 이어지지 않는다는 점입니다. 텍스트 반성은 빠르게 만들 수 있지만 문맥에서 검색·선택해야 하고, 모든 이력을 넣으면 입력 길이가 커집니다. 전체 모델을 미세조정하면 경험이 가중치에 남지만, 학습 비용과 기존 파라미터에 미치는 영향을 함께 관리해야 합니다. Self-Direction은 실패 하나마다 별도의 LoRA 교훈을 두고 필요할 때 선택하는 방식으로 이 간극을 다룹니다. [§1–2][s1]

독창성은 LoRA 자체보다 **검증된 실패를 개입 시점으로 삼고, 자기 반성에서 나온 교훈을 분리된 어댑터로 누적하는 운영 루프**에 있습니다. 같은 기반 모델이 작업 수행과 예제 합성에 사용되며, 정답이나 숨은 테스트를 반성 입력으로 전달하지 않습니다. 논문은 즉시 성공률뿐 아니라 같은 실패의 재발 방지와 새로운 과제에서의 재사용을 따로 평가합니다. [§3.3][s33] · [§4.2–4.4][s42] · [부록 F.2][af]

## 기술적 세부사항

어댑터는 큰 가중치 행렬에 작은 저랭크 수정량을 더합니다. Self-Direction은 기반 모델과 기존 교훈을 고정하고 새 어댑터의 한 인자만 학습합니다. 라이브러리에는 어댑터와 원래 과제 설명의 문장 임베딩을 함께 저장합니다. 이 임베딩은 텍스트의 의미를 벡터로 나타낸 값이며, 새로 실패한 과제와 유사한 교훈을 찾는 데 쓰입니다. 선택 임계값보다 충분히 가까운 항목이 없고 라이브러리에 자리가 남아 있으면 새 교훈을 만듭니다. [§3.3][s33] · [부록 F.5·J][aj]

이 설계는 “새 파라미터를 학습해도 원래 가중치를 덮어쓰지 않는다”는 저장상의 성질과, “선택된 어댑터가 이후 과제의 출력을 해치지 않는다”는 경험적 문제를 구분해야 이해할 수 있습니다. 잘못 연결된 어댑터는 성능을 낮출 수 있습니다. 그래서 논문은 검색 임계값, 실패 뒤에만 개입하는 순서, 어댑터를 내린 뒤의 기반 모델 재시도를 함께 분석합니다. [§4.3][s43] · [부록 E.1·C.8][ae]

## 챕터별 상세 리뷰

### 📖 **Chapter 1: Introduction**

서론은 같은 실수를 다시 고치는 비용에서 출발합니다. 긴 작업에는 도구 사용과 판단이 여러 번 필요하고, 한 번의 반성이 현재 세션을 고쳐도 다음 세션의 행동을 바꿨는지는 별개의 문제입니다. 저자들은 교훈을 문맥·하네스·가중치에 보관하는 접근을 비교하며 지속적인 개선에 필요한 조건을 제시합니다. 하네스는 모델을 호출하고 도구·문맥·상태를 관리하는 실행 구조를 뜻합니다. [§1][s1]

이어서 Self-Direction의 세 주장을 소개합니다. GAIA·Claw-Eval·Terminal-Bench 2.1에서 실패 복구를 개선하고, 같은 과제의 반복 조우에서도 교정을 더 자주 유지하며, 제한된 교훈 라이브러리를 관련 새 과제에 재사용할 수 있다는 것입니다. 이후 장은 이 세 종류의 결과를 각각 다른 실험으로 확인합니다. [§1, PDF 2–3쪽][p2]

### 📖 **Chapter 2: Related Work**

**문맥에 남긴 교훈.** Reflexion·ExpeL·CLIN 등은 반성이나 절차를 외부 메모리에서 찾아 입력에 넣습니다. 모델을 갱신하지 않아 빠르게 적용할 수 있지만, 필요한 경험을 매번 선택하고 제한된 문맥 안에서 전달해야 합니다. 논문은 텍스트 길이와 프롬프트 구성에 민감한 점을 기존 연구와 연결합니다. [§2][s2]

**하네스에 남긴 교훈.** 프롬프트·도구·메모리·실행 코드를 바꾸는 연구는 같은 모델이 더 효과적으로 일하도록 돕습니다. 이 논문은 실패를 계기로 삼는 점을 공유하면서 교정 내용을 정책 파라미터에 모듈로 저장하는 방향을 택합니다. **가중치에 남긴 교훈**을 다루는 마지막 부분에서는 전체 미세조정, 실패 자료 학습, Test-Time Training과 비교합니다. Self-Direction의 구분점은 확인된 실패에 반응하고, 더 강한 외부 교사 없이 예제를 생성하며, 교훈을 이후 검색할 수 있게 남기는 조합입니다. [§2][s2]

### 📖 **Chapter 3: Learning from Mistakes**

#### 3.1 Existing Paradigms for Repairing Mistakes

같은 실패를 복구하는 네 방식을 비교합니다. 기반 모델에서 독립적으로 다시 뽑는 resampling은 성공 기회를 늘립니다. 반성을 문맥에 넣으면 다음 행동을 안내합니다. 반성을 가중치에 학습하면 어댑터를 다시 불러 쓸 수 있습니다. `Skills.md` 방식은 여러 반성을 공유 Markdown 파일에 요약해 넣고 다음 작업의 입력에 사용합니다. 비교의 축은 **현재 복구에 쓰인 경험이 어디에 남아 이후 행동에 관여하는가**입니다. [§3.1][s31]

#### 3.2 Experimental Setup and Evaluation on GAIA

주 실험의 기반 모델은 Qwen3.6-27B이고, 도구의 실행 결과를 관찰한 뒤 다음 행동을 정하는 ReAct 루프를 사용합니다. GAIA 검증 과제는 165개로 난이도 1·2·3이 각각 53·86·26개입니다. 웹 검색·가져오기, Python, 셸, 파일 도구를 사용할 수 있고 최종 짧은 답을 참조와 대조합니다. Claw-Eval은 행동 로그·상태·산출물과 평가자를 함께 쓰며, Terminal-Bench는 새 컨테이너에서 종료 후 숨은 테스트로 검증합니다. 최종 문장만 맞으면 되는지와 행동까지 맞아야 하는지가 벤치마크마다 다릅니다. [§3.2][s32]

평가에서는 `pass@k`와 $`\mathrm{pass}^{k}`$를 구분합니다. 앞의 값은 독립 실행 k번 중 한 번 이상 성공한 과제 비율이고, 뒤의 값은 k번 모두 성공한 비율입니다. 여러 번 시도해 풀 수 있는 범위와 매번 안정적으로 푸는 정도를 나누어 보는 것입니다. [§3.2][s32]

| GAIA, 동일 초기 실행에서 시작 | 성공률 |
| --- | ---: |
| 최초 기반 모델 | 38.8% · 64/165 |
| 기반 모델 pass@3 | 49.7% |
| 문맥에 반성 삽입 | 45.5% |
| Skills.md에 반성 누적 | 53.3% |
| Self-Direction 전체 루프 | 55.8% · 92/165 |

표는 PDF 그림 2와 부록 C.9에서 대조했습니다. Self-Direction은 최초 실패 101개 중 어댑터로 21개, 기반 모델 fallback으로 7개를 추가 해결했습니다. 따라서 17.0%포인트 개선 전체를 어댑터 한 번의 효과로 해석하면 안 됩니다. 부록 C.2의 100단계 실행은 더 긴 순차 예산을 준 참고 비교입니다. [PDF 4쪽, 그림 2][p4] · [부록 C.2·C.9][ac]

#### 3.3 The Self-Direction Loop

실패가 확인되면 같은 모델이 궤적을 읽어 절차적 instruction–response 예제를 최대 24개 합성합니다. 도구를 어떤 순서로 쓰고 무엇을 확인해야 하는지 가르치는 짧은 예제이며, 과제 환경에서 끝까지 다시 실행한 rollout과 구분됩니다. 적어도 유효 예제 8개가 있어야 학습을 시작합니다. 더 강한 외부 모델이 교정 답안을 제공하는 구조는 사용하지 않습니다. [§3.3][s33] · [부록 F.2][af]

학습할 행렬의 오른쪽 특이벡터에서 LoRA의 인자 $`A`$를 초기화해 고정하고, 0에서 출발하는 $`B_i`$만 최적화합니다. 기반 모델은 그대로 두고 새 교훈 i에 해당하는 수정량만 학습합니다. 왜 이 초기화가 업데이트를 작게 제한하는지는 부록 J에서 수식으로 설명합니다. [§3.3][s33]

저장한 교훈을 재사용할 때는 `all-MiniLM-L6-v2`의 과제 설명 임베딩을 비교합니다. 일치도가 임계값 $`\tau`$보다 낮으면 새 교훈 학습을 검토합니다. 어댑터 재시도가 실패하면 이를 완전히 내리고 기반 모델로 한 번 더 시도합니다. 아래는 부록 F.5의 흐름을 정리한 설명용 의사코드입니다. [§3.3][s33] · [PDF 33쪽][p33]

가장 유사한 과제 설명의 교훈을 검색
교훈이 없거나 유사도가 임계값보다 낮으면:

#### 4.2 Learned Lessons Prevent Repeated Mistakes

GAIA 101개, Terminal-Bench 44개, Claw-Eval 40개의 **과거 실패 185개**를 다시 만나는 실험입니다. 각 조우에서 두 방식 모두 최대 두 번의 전체 실행을 받습니다. 모든 조우에서 성공한 실패의 비율을 mistakes avoided, 첫 조우에서 고친 것 중 이후에도 계속 성공한 비율을 corrections preserved로 계산합니다. 아래 표는 원문 표 1의 통합 행입니다. [§4.2][s42] · [PDF 9쪽, 표 1][p9]

| 세 번 조우까지의 지표 | 기반 모델 재시도 | Self-Direction |
| --- | ---: | ---: |
| 세 번 모두 해결한 과거 실패 비율 | 9.7% | 18.9% |
| 첫 교정 성공 중 두 번째까지 유지 | 52.4% | 76.9% |

18.9%는 전체 185개가 분모이고, 67.3%는 첫 조우의 교정 성공이 분모입니다. 후자를 전체 과제 성공률로 읽으면 의미가 달라집니다. 별도로 매 실행마다 전체 학습 루프를 새로 실행한 Terminal-Bench 세 번 캠페인에서는 pass@3이 64.0%→74.2%, pass³가 34.8%→57.3%였습니다. 그 캠페인과 하나의 저장된 교훈을 반복 활용하는 실험은 학습·실행 단위가 다릅니다. [§4.2][s42] · [PDF 8쪽, 그림 5][p8]

#### 4.3 Self-Direction Learns New Lessons Without Impacting Existing Capabilities

보존을 위한 첫 장치는 최초 시도를 언제나 수정되지 않은 기반 모델에 맡기는 것입니다. 이미 성공한 작업에 어댑터를 미리 적용하지 않습니다. 둘째는 기반 모델과 기존 어댑터의 파라미터를 고정하는 구조입니다. 이 상태에서 새 어댑터 학습은 기존 저장값을 덮어쓰지 않습니다. [§4.3][s43]

그러나 재시도에서 어떤 교훈을 고르느냐는 여전히 중요합니다. $`\tau=1`$이면 같은 과제에 해당하는 교훈만 재사용하고, 더 작은 임계값이면 비슷한 새 과제에서도 고를 수 있습니다. 부록 C.8은 다른 벤치마크의 교훈이 잘못 검색되지 않을 임계값과, 이를 낮췄을 때 실제 복구 성능을 별도로 살펴봅니다. 논문은 매우 낮은 임계값에서 도움이 되거나 해가 되는 전이가 나타날 수 있다고 보고합니다. [§4.3][s43] · [부록 C.8][ac]

#### 4.4 Learned Lessons Transfer to Unseen Tasks Across Difficulties and Types

세 전이 실험은 라이브러리를 언제 학습하고 무엇을 고정했는지가 다릅니다. 첫째는 GAIA 165개를 섞어 순차로 만나며 처음부터 라이브러리를 채우는 배포 흐름입니다. 용량을 어댑터 세 개로 제한한 설정에서 성공률은 36.4%→52.7%였고, 저장 라이브러리는 약 256MB입니다. 이 초기 성공률은 앞의 진단 GAIA 실행 38.8%와 같은 실행으로 취급하지 않습니다. [§4.4][s44] · [부록 C.1·C.7][ac]

둘째는 쉬운 Level 1 실패에서 학습한 어댑터 28개를 고정하고, 보지 않은 Level 2 과제 86개를 평가하는 실험입니다. 초기 35개 성공에 9개 복구를 더해 40.7%→51.2%가 됐습니다. 셋째는 Claw-Eval operations 과제에서 만든 어댑터 세 개만 고정해 새 workflow 과제 24개에 사용합니다. 초기 18개 성공 후 남은 6개 중 3개를 복구해 75.0%→87.5%가 됐습니다. 뒤의 두 실험은 평가 과제에서 새 교훈을 학습하지 않았습니다. [§4.4][s44] · [PDF 17쪽, 표 3][p17]

#### C.9 · GAIA 통계 검정

분석 단위는 실행 횟수가 아니라 개별 GAIA 과제입니다. 최초 성공 여부 $`B_i`$와 전체 루프의 최종 성공 여부 $`S_i`$를 0·1로 두고 차이 $`D_i=S_i-B_i`$를 구합니다. 165개 중 64개는 둘 다 성공, 28개는 루프 후 새 성공, 73개는 둘 다 실패했습니다. [부록 C.9][ac]

```math
\overline D=\frac{28}{165}\approx0.1697
```

```math
t=\frac{\overline D}{s_D/\sqrt{165}}
```

$`s_D`$는 165개 차이의 표본 표준편차입니다. 저자의 짝지은 t 검정은 t(164)=5.79, 양측 p=3.50×10⁻⁸이고 정확도 개선의 95% 신뢰구간은 [11.2, 22.8]%포인트입니다. 이 검정과 구간은 GAIA의 초기 실행 대 전체 루프 비교에 대응합니다. [부록 C.9, PDF 21쪽][p21]

### 📖 **Chapter J: Benefits of SVD Initialization**

기반 가중치 $`W`$의 큰 에너지를 가진 오른쪽 특이 부분공간에서 rank 16 인자 $`A`$를 구해 고정합니다. 교훈 i는 그 입력 방향을 이용해 새 출력 방향으로 연결하는 $`B_i`$만 학습합니다. 초기 $`B_i=0`$이므로 학습 전 어댑터의 수정량은 정확히 0입니다. 원문의 관계식은 다음과 같습니다. [부록 J][aj]

```math
W_i=W+\Delta W_i
```

```math
\Delta W_i=B_iA
```

교정 데이터 $`D_i=\{(u_j,v_j)\}_{j=1}^{N_i}`$에서 $`u_j`$는 지시, $`v_j`$는 절차적 응답입니다. 원문 학습 목표를 두 줄로 나누면 아래와 같습니다. [부록 J][aj]

```math
\mathcal L_i(\phi_i)=
-\frac{1}{N_i}\sum_{j=1}^{N_i}
\log p_{\theta,\phi_i}(v_j\mid u_j)
```

```math
\phi_i^*=\arg\min_{\phi_i}\mathcal L_i(\phi_i),
\qquad \theta\;\mathrm{fixed}
```

$`\theta`$는 고정 기반 파라미터, $`\phi_i`$는 새 어댑터에서 학습하는 B 인자입니다. 예제 응답의 확률을 높이는 교차엔트로피 학습이며, 실제 최적화는 2 epoch의 설정을 따릅니다. 저자들은 선택한 부분공간이 같은 차원의 무작위 공간보다 약 16–22배의 기반 가중치 에너지를 담는다고 보고합니다. 학습한 출력 방향은 대체로 새로운 방향이어서 단순히 기반 가중치를 더 크게 만드는 업데이트로 설명하지 않습니다. [부록 J][aj]

## 실험 결과 심층 분석

이 논문의 결과는 세 단위로 읽어야 합니다. 즉시 복구는 최초 실행 뒤 어댑터와 fallback까지의 **전체 루프**를 봅니다. 교정 유지 실험은 같은 과거 실패를 재조우하며 **이미 저장한 교훈**을 봅니다. 새 과제 전이는 시점 이전의 라이브러리를 쓰거나 별도 학습 과제에서 만든 라이브러리를 고정해 **보지 않은 과제의 복구**를 봅니다. 숫자들이 모두 정확도라 해도 학습과 평가에서 허용한 경험의 범위가 다릅니다. [§4.1–4.4][s4]

GAIA의 95% 신뢰구간은 과제별 짝지은 초기 대 최종 결과에 붙습니다. Claw-Eval·Terminal-Bench의 주 ±값은 세 번 실행의 표준편차이고, 외부 프런티어 모델은 다른 하네스의 보고 점수입니다. 과제 환경 실행 횟수를 맞춘 그림 10에는 GPU 학습과 합성 비용이 빠져 있어, 전체 비용 판단에는 H200의 평균 교훈 준비 8.16분과 저장량을 함께 봐야 합니다. [부록 C.9][ac] · [부록 F.3][af]

## 기술적 함의와 응용

Self-Direction은 실패 로그를 다음 행동의 조건으로만 쓰는 데서 더 나아가, 필요할 때 연결할 수 있는 파라미터 모듈로 남깁니다. 리뷰의 관점에서 실무적 질문은 교훈을 얼마나 많이 모았는가와 함께, 언제 실패로 판정했고 어떤 과제에 어떤 교훈을 연결했는가입니다. 기반 모델 저장값을 보존하는 구조, 검색 임계값에 따른 적용 범위, 어댑터를 내린 fallback이 각각 다른 역할을 맡기 때문입니다. [§3.3·4.3][s33] · [부록 F.5][af]
