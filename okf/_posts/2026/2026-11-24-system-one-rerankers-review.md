## 논문 개요와 전체 구조

검색 결과 100개를 가져온 뒤, 그중 질문에 가장 잘 답하는 문서를 위로 올리는 모델을 **리랭커(reranker)**라고 합니다. RAG에서 검색한 자료를 답변 모델에 넘기기 전에 거치는 정리 단계입니다. 그런데 어떤 모델이 문서마다 “이 문서가 답일 확률은 90%”처럼 숫자를 준다면, 그 숫자로 정렬해도 좋은 리랭커가 될까요?

Michael Dinzinger, Kanishka Ghosh Dastidar, Michael Granitzer의 *System One Models Are Not Better Rerankers*는 이 질문을 같은 기반 모델끼리 비교합니다. 일반적인 판단을 확률로 내놓도록 학습한 **System One 모델**과, 검색 결과의 관련성을 구분하도록 학습한 전용 리랭커를 비교한 논문입니다. 중요한 구분은 두 가지입니다. **좋은 문서를 앞에 놓는 능력**과 **90%라는 숫자가 실제 90%에 가까운지**는 따로 확인해야 합니다. [원문 v1](https://arxiv.org/html/2610.32318v1)

## 핵심 기여와 혁신성

검색 시스템에서는 문서의 순위를 잘 매기는 일이 먼저입니다. 한편 “확률 0.5 이상인 문서만 답변 모델에 전달하자”처럼 점수 자체로 결정을 내릴 때도 있습니다. 저자들은 이 두 용도를 **순위 평가와 확률 보정 평가로 나눕니다.** 확률을 그럴듯하게 내놓는 모델이라도 관련 문서를 가려내지 못하면 검색 품질은 낮을 수 있기 때문입니다.

기존 Jev 활용 보고는 다른 크기·계열의 리랭커와 비교했습니다. 그 결과만으로는 좋은 성능이 판단 학습 덕분인지, 원래 기반 모델이 강해서인지 분리하기 어렵습니다. 이 연구는 **동일한 Qwen 기반 모델의 일반 채팅 버전, 판단 학습 버전, 리랭킹 학습 버전**을 같은 BM25 상위 100개 후보 위에서 비교합니다. 9B와 27B에서는 저자들이 직접 단순한 학습법으로 만든 리랭커도 대조군에 넣었습니다.

또 하나의 기여는 “관련이 있나요?”라는 문장의 의미까지 평가에 포함한 점입니다. 질문을 “답을 제공하나요?”로 좁혔을 때와 “직접 관련된 정보도 포함하나요?”로 넓혔을 때, 순위 변화는 작지만 확률 보정은 크게 달라졌습니다. **확률을 해석하려면 무엇을 정답으로 세는지 먼저 맞춰야 한다**는 결과입니다. 아래에서는 이 실험이 어떤 조건에서 나온 것인지 원문 순서대로 살펴봅니다.

## 기술적 세부사항

BM25는 검색어와 문서의 단어 일치 등을 이용해 후보를 찾는 첫 단계 검색기입니다. 여기서는 모든 모델이 BM25가 고른 같은 100개를 다시 정렬합니다. 모델이 더 좋은 문서를 새로 찾아오는 실험은 아닙니다.

판단 모델은 입력 상태와 질문을 받고 예·아니요 확률을 돌려줍니다. **isolated**는 질문과 문서 한 개만 보여 주고, **joint**는 질문과 후보 100개를 한꺼번에 보여 준 뒤 문서별로 물어봅니다. 원문 3절의 관계를 표기하면 다음과 같습니다.

```math
\begin{aligned}
p_i^{\mathrm{isolated}}&=P(\mathrm{yes}\mid q,d_i),\\
p_i^{\mathrm{joint}}&=P(\mathrm{yes}_i\mid q,d_1,\ldots,d_{100}).
\end{aligned}
```

$`q`$는 검색 질문, $`d_i`$는 i번째 후보 문서, $`p_i`$는 그 문서가 답이라는 모델의 확률입니다. joint의 $`\mathrm{yes}_i`$ 아래첨자는 “i번째 문서에 대한 질문”임을 분명히 하려고 붙인 리뷰 표기입니다. 어느 방식이든 최종 정렬은 확률이 큰 순서입니다. joint라고 해서 모델이 문서들의 최종 순번을 직접 출력하는 것은 아닙니다. [원문 3절](https://arxiv.org/html/2610.32318v1#S3)

| 평가 대상 | 지표와 해석 |
| --- | --- |
| 상위 문서의 순서 | nDCG@10: 정답 관련성이 높은 문서를 상위 10개 앞쪽에 두는 정도. 표에서는 원래 값을 100배 해 표시합니다. |
| 확률값의 보정 | ECE: 비슷한 확률을 낸 사례들을 묶어 예측 확률과 실제 관련 문서 비율의 차이를 측정합니다. 이 논문은 같은 폭의 15구간을 씁니다. 작을수록 좋습니다. |
| 확률의 제곱 오차 | Brier score: 확률과 0·1 정답의 평균 제곱 오차. 보정뿐 아니라 정답과 오답을 구별하는 정도도 반영합니다. |
| 0.5 기준으로 남긴 문서 집합 | F1@.5: 확률 0.5 이상인 문서의 정밀도·재현율을 함께 봅니다. |
| 관련 문서 개수 추정 | 판단이 붙은 문서의 확률을 합한 값과 실제 관련 문서 수의 평균 절대 오차. 단위는 문서 개입니다. |

예를 들어 확률 0.8을 받은 문서들을 많이 모았을 때 약 80%가 실제 관련 문서라면 보정이 잘 된 것입니다. 이것만으로 특정 질문의 가장 유용한 문서가 맨 앞에 온다는 뜻은 아닙니다. 반대로 순위가 좋아도 점수가 모두 지나치게 낮으면 0.5 필터에서 좋은 문서를 버릴 수 있습니다. 이것은 지표의 뜻을 설명한 예시이며, 논문의 측정 결과를 새로 만든 것은 아닙니다.

## 챕터별 상세 리뷰

### 📖 **Chapter 1: Introduction**

도입부는 판단 모델의 등장과 검색 활용을 연결합니다. 저자들이 부르는 System One 모델은 긴 답변을 생성하는 대신, 입력에 대한 질문의 답을 보정된 확률로 주는 모델입니다. 이름은 빠르고 직관적인 판단을 가리키는 “System 1”에서 왔습니다. 이 논문에서 판단 모델은 Jev와 공개 모델 Kev·Clef 등을 뜻하며, 사고 과정을 길게 출력하는 추론 모델 전체를 묶는 말은 아닙니다.

원문은 Jev가 2026년 9월 15일 공개된 뒤 빠르게 리랭커로 사용됐다고 설명합니다. 다만 Jev의 학습법 RLCD는 공개되지 않았습니다. Kev·Clef처럼 공개 Qwen 모델에서 출발한 판단 모델이 등장하면서, 이제 같은 기반 모델의 전용 리랭커와 비교할 수 있게 됐다는 것이 연구의 출발점입니다.

저자들은 연구 질문을 다음처럼 나눕니다. **RQ1**은 판단 학습이 같은 기반 모델의 일반 채팅 버전이나 전용 리랭킹 학습보다 순위를 더 잘 매기는가입니다. **RQ2**는 관련성 확률이 더 잘 보정돼 있고, 그 보정이 실제 선택에 도움이 되는가입니다. 같은 모델을 비교한다는 설계와 점수의 두 용도를 분리한다는 설계가 함께 필요합니다.

### 📖 **Chapter 2: Related Work**

**LLM-based rerankers.** 첫 소주제는 질문–문서 쌍에 관련성 점수를 주는 신경망 리랭커의 흐름입니다. 초기 인코더·시퀀스 모델에서 최근 LLM 기반 모델로 이어지며, Qwen3-Reranker와 Prism은 예·아니요 토큰의 확률을 이용합니다. 따라서 판단 모델과 출력 형태를 맞춰 비교할 수 있습니다. 후보들을 함께 읽고 목록 순서를 생성하는 방식, 문서끼리 주의를 주고받는 Set-Encoder도 관련 접근으로 구분합니다.

미세 조정하지 않은 LLM에 관련성을 물어보는 방법도 있습니다. 다만 프롬프트 문구에 민감합니다. 이 연구가 일반 채팅 모델을 대조군에 넣는 이유는 판단 학습이 이 기본 지시 수행 능력 위에 무엇을 더하는지 확인하기 위해서입니다.

**Decision models in retrieval.** 다음으로 Jev·Kev·Clef·Laya를 다룹니다. 저자들은 당시 검색 활용 근거가 동료 심사를 거치지 않은 보고에 주로 의존한다고 설명합니다. 다른 기반 모델의 기존 리랭커와 비교한 사례들은 있었지만, 같은 기반 모델에서 학습 방식의 이득과 보정의 실용성을 함께 분리하지는 않았다는 지적입니다. 이 리뷰는 해당 보고들의 결과를 별도로 재검증한 것으로 쓰지 않습니다.

**Calibration of relevance scores.** 마지막 소주제는 점수의 보정입니다. 문서 순위만 최적화하면 한 질문의 모든 점수에 같은 값을 더해도 순서는 유지될 수 있습니다. 그러므로 순위를 잘 학습했다고 해서 점수가 바로 확률의 뜻을 갖는 것은 아닙니다. 저자들은 학습 중 보정과 학습 후 temperature scaling 등을 기존 방법으로 소개한 뒤, 목록을 어디서 자를지 결정하는 용도로 넘어갑니다. 이 구분을 다음 3절에서 실제 입력·출력 형태로 정의합니다. [원문 2절](https://arxiv.org/html/2610.32318v1#S2)

### 📖 **Chapter 3: Decision Models as Rerankers**

이 절은 판단 모델의 입력인 **state**를 먼저 정의합니다. state는 모델이 판단할 자료입니다. 검색에서는 질문과 문서 한 개, 혹은 질문과 후보 목록 전체가 됩니다. 모델은 각 문서가 질문에 답하는지 묻는 이진 질문마다 하나의 확률을 줍니다. 확률을 내림차순 정렬하면 리랭킹 결과가 됩니다.

isolated에서는 각 문서가 다른 후보와 독립적으로 입력됩니다. joint에서는 100개 후보를 BM25 순서로 한 상태에 담으므로 다른 후보의 내용이 개별 문서의 점수에도 영향을 줄 수 있습니다. 저자들은 joint가 listwise 방식과 같은 입력을 보더라도, 출력은 문서별 점수이므로 두 설정 모두 pointwise 리랭커라고 분류합니다. **전체를 같이 읽는가와 전체 순서를 직접 생성하는가는 다릅니다.**

이어지는 **Terms**는 비교군을 고정합니다. 일반 모델은 순위나 판단을 위해 추가 학습하지 않은 공개 채팅 모델로, 자신의 채팅 형식에서 같은 질문을 받고 첫 답변 토큰의 예 확률을 줍니다. 판단 모델은 Kev·Clef처럼 판단 작업용으로 미세 조정한 모델입니다. 전용 리랭커는 관련성 라벨로 미세 조정됐으며, 자기 고유 프롬프트와 예·아니요 확률을 유지합니다. 모든 모델의 프롬프트를 똑같이 바꾼 실험은 아닙니다.

다음은 원문 3절을 따라 다시 쓴 절차입니다. 실제 공개 코드의 인용이나 실행 결과가 아닌 **설명용 의사코드**입니다.

```text
입력: 질문 q, BM25 상위 후보 D=[d1, ..., d100], 입력 방식 mode
각 문서 di에 대해:
    mode가 isolated이면 state = (q, di)
    mode가 joint이면 state = (q, D)
    pi = state에서 di가 질문에 답할 확률
출력: pi가 큰 순서로 정렬한 후보 목록
별도 선택 평가: pi >= 0.5인 문서만 남긴 집합
```

순위와 별도 선택을 구분한 이 절차는 4절의 두 평가 경로로 이어집니다.

### 📖 **Chapter 4: Experimental Setup**

**Backbones and variants.** 기반 모델은 Qwen3-0.6B·8B, Qwen3.5-0.8B·4B·9B, Qwen3.8-27B의 여섯 종류입니다. 일반 모델은 thinking을 끄고 평가합니다. Kev는 모든 크기에 있고, Clef-Flash는 9B, Clef는 27B 대조군입니다. 판단 모델은 isolated와 joint로 각각 실행합니다. Kev의 9B 이하 모델은 사전학습 체크포인트의 LoRA 미세 조정이며, Kev-27B는 공개 채팅 모델 전체를 미세 조정했습니다. 크기 외에 학습 출발점과 방식도 달라집니다.

저자들은 공개 판단 모델이 Jev와 같은 종류의 출력을 학습했을 뿐, 공개되지 않은 RLCD를 재현한 모델은 아니라고 명시합니다. 전용 리랭커는 0.6B·8B의 Qwen3-Reranker, 0.8B·4B·9B의 Prism입니다. 따라서 결과는 평가한 공개 모델과 학습 절차에 대한 근거이며 RLCD 자체를 통제한 실험은 아닙니다.

**Our reranker fine-tunes.** 27B 전용 리랭커가 없어서 저자들이 Ours-27B를 만들고, 같은 학습법이 작은 크기에서도 통하는지 확인하려고 Ours-9B를 추가합니다. LoRA rank 32, MS MARCO 학습 질문 10만 개, 한 epoch입니다. 질문마다 관련 문서 한 개와 어려운 오답 15개를 사용하며, 오답은 dense retriever에서 8개, BM25에서 7개를 가져옵니다. 그룹 안에서 정답을 올리는 InfoNCE와 각 문서의 예·아니요를 구별하는 이진 교차 엔트로피를 함께 씁니다. 후자는 점수 자체에도 의미를 주려는 구성입니다.

테스트·개발 주제와 일치하는 학습 질문을 제거하고, 개발 질문 200개에 미리 정한 규칙으로 체크포인트를 고릅니다. 판단 데이터나 하이퍼파라미터 탐색은 사용하지 않았습니다. Qwen3-Reranker·Prism·자체 리랭커는 MS MARCO 학습 데이터를 봤지만, Kev 학습 데이터에는 MS MARCO와 BEIR가 없다는 차이도 공개합니다.

**The question.** 주 평가에서는 “이 문서가 질문에 답하는가”를 묻습니다. TREC DL에서 관련 문서를 등급 2 이상으로 정의한 평가와 맞추려는 문구입니다. 실험 전에 고정했지만 개발 데이터로 최적화하지는 않았습니다. 다른 문구는 S1Rank의 더 넓은 관련성 질문 하나만 시험하며, 전용 리랭커는 자기 프롬프트를 유지합니다.

**Collections and candidates.** TREC DL 2019–2023 다섯 개와 BEIR의 TREC-COVID·NFCorpus·SciFact·Touché·DBPedia 다섯 개, 총 열 컬렉션입니다. 모든 모델이 같은 Pyserini BM25 상위 100개를 받습니다. 어느 미세 조정 모델도 학습하지 않은 TREC-COVID·Touché·DBPedia를 **zero-shot 부분집합(ZS)**으로 따로 집계합니다. ZS는 해당 세 컬렉션 평균이며, 열 컬렉션 전체 평균과 분모가 다릅니다.

**Other systems.** 문맥 비교에는 BM25, 닫힌 Jev 1.13.0, Laya, monoT5-3B, bge-reranker-v2-m3, Set-Encoder, RankZephyr, RankGPT-4를 넣습니다. Laya는 문맥 길이 때문에 isolated만 실행합니다. Table 2의 †는 같은 후보에 대한 기존 발표값으로, 저자들이 다시 측정한 값과 구분합니다. 서로 다른 기반 모델의 이 비교는 시장 전체의 위치를 보는 보조 자료이며, 학습 방식의 효과를 분리하는 주 실험과는 역할이 다릅니다.

**Ranking.** 순위 지표는 nDCG@10입니다. 질문별 대응 t 검정을 하고 열 컬렉션에 걸쳐 Holm 보정을 적용하며 유의수준은 0.05입니다. 기반 모델마다 전용 리랭커 대 평균 순위가 가장 좋은 판단 모델, 그 판단 모델 대 일반 모델, joint 대 isolated를 비교합니다. 보정 평가 표가 고르는 모드와 순위 표가 고르는 모드가 같다고 가정하면 안 됩니다.

**Calibration and its uses.** 보정은 관련 없는 문서에도 충분한 판정이 있는 TREC DL에서, 실제 판단이 붙은 질문–문서 쌍만 사용합니다. ECE 15구간과 Brier score를 계산합니다. 0.5 필터의 F1 평가에서는 판단되지 않은 문서를 비관련으로 셉니다. 임계값을 나중에 컬렉션별로 가장 유리하게 골랐을 때의 F1과 0.5 F1의 차이를 **regret**로 부릅니다. 작으면 기본 임계값이 최선의 임계값과 가깝다는 뜻입니다.

관련 문서 수 추정은 판단된 문서들의 확률을 더합니다. 원문 설명을 수식으로 옮기면 다음과 같습니다. 원문에 별도 번호로 제시된 새 추정기는 아닙니다.

```math
\widehat{N}_q=\sum_{i\in J_q}p_i
```

$`J_q`$는 해당 질문에서 판정이 붙은 문서의 집합이고, $`\widehat{N}_q`$는 그 안의 관련 문서 수 추정값입니다. 문서마다 관련될 확률을 더하면 관련 개수의 기댓값이 됩니다. 문서 사이의 독립성을 가정해서 곱하는 계산은 아닙니다. 모델 간 비교에서는 이 추정과 실제 관련 수의 평균 절대 오차를 사용합니다. 컬렉션별 중앙값만 늘 예측하는 기준선의 오차는 8.6개입니다.

사후 보정은 테스트 데이터 대신 MS MARCO 개발 질문 1,000개에서 temperature scaling과 Platt scaling을 맞춥니다. 학습용 분포에서 맞춘 확률이 다른 평가 분포에도 통하는지 확인하는 구성입니다.

**Sanity checks.** 마지막으로 재현 오차를 확인합니다. BM25·monoT5-3B·RankZephyr는 발표값과 nDCG@10 0.2점 이내입니다. S1Rank 문구의 Jev joint는 다섯 컬렉션 중 네 개에서 0.5점 이내이고 TREC-COVID에서는 1.5점 낮습니다. 저자들은 이 차이를 감춘 채 완전히 같다고 하지 않습니다. 이렇게 비교 조건을 점검한 다음 5절에서 순위 결과를 다룹니다. [원문 4절](https://arxiv.org/html/2610.32318v1#S4)

### 📖 **Chapter 5: RQ1: Decision vs. Reranker Fine-Tuning**

**Reranker fine-tuning beats decision fine-tuning.** 첫 결과는 작은 모델부터 9B까지의 순위 차이입니다. Table 1의 열 컬렉션 평균을 간추리면 다음과 같습니다. 판단 모델 열은 그 기반 모델에서 평균 순위가 가장 좋은 모델·모드를 골랐습니다. 수치는 모두 nDCG@10을 100배 한 점수입니다.

| 기반 모델 | 일반 모델 | 최선의 판단 모델 | 전용 리랭커 |
| --- | --- | --- | --- |
| Qwen3-0.6B | 26.6 | Kev isolated 27.3 | Qwen3-Reranker 56.1 |
| Qwen3-8B | 51.1 | Kev isolated 51.7 | Qwen3-Reranker 59.4 |
| Qwen3.5-0.8B | 33.9 | Kev isolated 34.2 | Prism 57.1 |
| Qwen3.5-4B | 52.4 | Kev isolated 49.9 | Prism 58.7 |
| Qwen3.5-9B | 53.1 | Clef-Flash isolated 53.8 | Prism 59.0／Ours 59.4 |
| Qwen3.8-27B | 56.4 | Kev joint 60.1 | Ours 59.6 |

출처: [Table 1](https://arxiv.org/html/2610.32318v1#S3.T1). 각 행은 같은 기반 모델이며, 별도 모델 계열 사이의 크기 통제 비교가 아닙니다.

0.6B에서는 전용 리랭커가 28.8점, 9B에서 Prism을 기준으로 하면 5.2점 높습니다. **5.2점은 상대 개선율 5.2%가 아니라 100배 표시된 nDCG의 점수 차이**입니다. 원문이 집계한 전용 리랭커–컬렉션 조합 60개 중 48개에서 차이가 통계적으로 유의하며, 판단 모델이 유의하게 앞선 경우는 없었습니다. 원문의 검정·비교군을 벗어나 모든 셀의 차이가 유의하다고 확대하지 않습니다.

학습 컬렉션 노출만으로 설명되는 결과도 아닙니다. ZS 세 컬렉션에서 전용 리랭커의 차이는 5.4–23.9점입니다. 자체 학습한 Ours-9B도 전체 평균 59.4로 Prism-9B의 59.0과 비슷하고, ZS 평균은 각각 56.1과 53.7입니다. 이 대조는 공개 리랭커의 비공개 학습 비결만 있어야 이 차이가 난다는 해석을 약화합니다. 다만 학습 데이터와 목적을 완전히 같게 만든 실험은 아니라는 7절의 범위는 남습니다.

27B에서는 Ours-27B 59.6, Kev joint 60.1로 비슷하며 ZS도 54.9와 55.0입니다. 유의한 차이는 DBPedia에서 Ours가 앞선 한 컬렉션뿐입니다. 저자들이 “동률”이라고 정리한 것은 이 실험 비교의 요약이며 두 시스템의 모든 지표가 동일하다는 뜻은 아닙니다.

**Up to 9B, decision fine-tuning adds nothing over the untuned model.** 다음 비교는 판단 학습이 일반 모델 위에 더한 이득입니다. 최선 모드 기준 9B 이하 판단 모델은 일반 모델 대비 −2.5~+0.7점 범위였고, 유의한 개선은 많아야 열 컬렉션 중 세 개였습니다. 전용 리랭킹 학습은 같은 기반에서 5.9–29.5점을 더합니다. 27B에서는 Kev가 3.7점, Ours가 3.2점을 더하지만, 같은 크기의 Clef는 이득을 보이지 않습니다. 따라서 27B라는 크기만으로 판단 학습의 이득을 설명할 수 없습니다.

**Context.** Table 2의 외부 비교에서 Jev joint는 59.1, Kev-27B joint는 60.1, Ours-27B는 59.6입니다. Jev가 좋은 리랭커라는 관찰과, 판단 학습이 전용 리랭킹 학습보다 좋다는 주장은 구분해야 합니다. 공개 강한 기반 모델의 전용 학습도 비슷한 수준에 도달했습니다. Laya의 43.5는 BM25 후보 순서의 43.2에서 큰 개선을 보이지 않습니다.

**Joint scoring helps only the largest models.** 후보를 같이 보여 주는 효과도 크기별로 갈립니다. Kev-27B는 59.0에서 60.1, Clef는 53.9에서 54.8로 약 1점 좋아집니다. 반면 Kev-0.6B는 27.3에서 15.1, Kev-8B는 51.7에서 38.7로 내려갑니다. 원문은 긴 입력을 가능한 설명으로 제시합니다. joint 상태는 TREC DL에서 약 13,000토큰, BEIR에서 40,000토큰 이상인데, 일부 작은 Kev 모델의 학습 상태 길이는 최대 7,552토큰, Kev-27B는 최대 32,768토큰으로 보고됐습니다. 이는 원문의 해석이며 길이 하나의 인과 효과를 별도 통제해 입증한 결과로 쓰지는 않습니다. 순위에 대한 답을 낸 뒤, 6절은 같은 점수를 확률로 읽어도 되는지 살펴봅니다. [원문 5절](https://arxiv.org/html/2610.32318v1#S5)

### 📖 **Chapter 6: RQ2: Are Decision Models Better Calibrated?**

**Asked our question, decision models are well calibrated.** 답을 제공하는지 묻는 주 문구에서, 판단 학습은 모든 기반 모델의 일반 모델보다 ECE를 줄입니다. Qwen3-8B 0.231에 비해 Kev joint는 0.113입니다. 4B 이상에서는 공개 전용 리랭커보다도 ECE가 낮습니다. 하지만 0.6B·0.8B에는 이 비교 우위가 그대로 성립하지 않습니다.

또한 “공개 전용 리랭커보다 우수”를 모든 전용 학습 방식보다 우수하다는 뜻으로 읽으면 안 됩니다. 자체 학습 Ours-9B의 ECE는 0.111, Clef-Flash는 0.112로 비슷합니다. 판단 데이터가 없어도 예·아니요 분류 손실을 함께 쓴 리랭커가 비슷한 보정에 도달한 사례입니다. 연구 내 가장 낮은 ECE는 Jev 0.075와 Kev-27B 0.076입니다.

**The advantage depends on the question.** 두 번째 소주제는 질문 문구 실험입니다. “답을 주는가” 대신 S1Rank의 “답을 주거나 직접 관련된 정보를 포함하는가”로 넓히면, 판단 모델의 전체 평균 순위 변화는 −2.5~+2.6점입니다. 여전히 9B 이하에서는 가장 좋은 판단 모델도 전용 리랭커보다 4점 이상 뒤처집니다. 반면 확률의 보정은 크게 달라집니다.

| 모델·모드 | 넓은 관련성 문구 ECE | 답 제공 문구 ECE | 전체 평균 nDCG 변화: 답 문구 − 넓은 문구 |
| --- | --- | --- | --- |
| Jev joint | 0.224 | 0.075 | −1.4점 |
| Kev-8B joint | 0.243 | 0.113 | −0.1점 |
| Kev-27B joint | 0.156 | 0.076 | −1.0점 |
| 일반 Qwen3-8B | 0.383 | 0.231 | −2.2점 |

출처: [Table 4](https://arxiv.org/html/2610.32318v1#S6.T4). ECE는 TREC DL의 판정된 쌍에서 계산하며, 순위 변화는 열 컬렉션 평균입니다.

Jev의 순위는 1.4점 내려가는데 ECE는 약 3분의 1이 됩니다. 모델이 정답을 더 잘 정렬해서라기보다 질문의 관련성 정의가 평가 라벨과 맞아진 결과로 해석해야 합니다. 일반 모델도 같은 문구 변경에서 이득을 봅니다. 저자들은 이런 문구 선택이 판단 모델 사용자의 책임이 되며, 전용 리랭커의 관련성 정의는 학습 라벨에 고정돼 있다는 차이를 짚습니다.

![문서를 순서대로 놓는 평가와 확률 기준으로 남기는 평가가 갈라지는 도식]({{ '/img/reviews/2026/system-one-rerankers-review/ranking-and-calibration.svg' | relative_url }})

문서별 확률을 받은 뒤 정렬과 임계값 선택은 서로 다른 평가로 이어집니다. 리뷰어 작성 도식이며 새로운 측정값은 없습니다. 출처: [원문 3·4·6절](https://arxiv.org/html/2610.32318v1#S6).
{: .caption}

**Calibration does not make up for a worse ranking.** 다음은 확률 0.5 이상만 남긴 결과입니다. Kev-4B는 Prism-4B보다 ECE가 낮지만, 남긴 집합의 F1은 42.6 대 51.0으로 낮습니다. 확률 구간 평균이 잘 맞더라도 개별 문서를 충분히 구별하지 못하면 유용한 문서 집합은 나빠질 수 있습니다. 이것이 RQ2에서 보정과 선택 품질을 나눠 읽어야 하는 이유입니다.

판단 모델의 regret는 0.9–3.1점으로 0.5가 사후 최적 임계값에서 아주 멀리 떨어진 것도 아닙니다. 원문은 임계값을 조금 움직이는 것만으로 순위 차이를 만회하기 어렵다고 해석합니다. 반면 순위가 비슷한 27B에서는 Kev의 F1 57.2가 Ours의 48.3보다 높습니다. Ours-27B는 0.5에서 평균 7.9개만 남기며 낮은 확률을 주는 경향을 보입니다. 보정의 효용 자체가 없다는 결론은 아닙니다.

**Counting relevant passages.** 이어 확률 합으로 관련 문서 수를 추정합니다. Kev-8B의 평균 오차는 7.6개로, 같은 기반의 Qwen3-Reranker-8B 12.9개나 중앙값 기준선 8.6개보다 작습니다. 그러나 일반 Qwen3.8-27B의 오차 5.8개가 전체에서 가장 낮고, Ours-9B 7.3개도 Clef-Flash 8.1개보다 낮습니다. 판단 학습만의 고유 장점이라고 부르기 어렵습니다. 넓은 관련성 문구에서는 가장 좋은 판단 모델 Clef joint도 8.4개로 중앙값 추정과 거의 차이가 없습니다.

**Calibration after the fact.** 마지막은 사후 보정입니다. temperature scaling은 Qwen3-Reranker-0.6B의 ECE를 0.511에서 0.326으로 낮추지만 다른 모델의 변화는 작습니다. Platt scaling을 적용하면 전용 리랭커의 0.5 필터 F1이 8.1 이하로 떨어집니다. MS MARCO 개발 데이터는 질문당 관련 문서가 약 한 개지만 TREC DL에는 훨씬 많아, 그 분포에서 맞춘 확률을 옮기면 지나치게 낮게 추정한다는 설명입니다. 보정은 관련성의 정의뿐 아니라 **관련 문서가 얼마나 흔한가**에도 묶입니다. 이 결과가 7절의 해석과 범위 제한으로 이어집니다. [원문 6절](https://arxiv.org/html/2610.32318v1#S6)

### 📖 **Chapter 7: Discussion and Limitations**

**Why decision fine-tuning does not make a reranker.** 저자들의 첫 해석은 학습 목적의 차이입니다. 전용 리랭커는 어려운 오답들 사이에서 관련 문서를 구별하는 작업을 학습하지만, 평가한 판단 모델은 여러 종류의 상태와 질문에 답하는 일반 판단을 학습했습니다. 9B 이하에서 그 전이가 일반 모델의 지시 수행 능력을 크게 넘지 못한다는 결과와 연결됩니다. ZS에서도 차이가 남아 특정 테스트 도메인의 학습 여부만으로 설명되지 않는다고 봅니다.

**Why 27B is different.** Kev-27B는 크기뿐 아니라 전체 미세 조정·채팅 체크포인트·긴 상태 학습에서도 작은 Kev와 다릅니다. 저자들은 이 중 무엇이 중요했는지 구별할 수 없다고 명시합니다. 같은 기반의 Clef에는 이득이 없고, 일반 27B도 이미 순위를 잘 매겨 추가 학습의 개선 폭이 작다는 사실을 함께 듭니다. “큰 모델이면 joint가 해결된다”처럼 이 실험 밖의 법칙을 만들지는 않습니다.

**What calibration means for relevance.** 보정은 정답 정의와 관련 문서의 비율에 대한 성질입니다. 이 연구에서는 질문 문구, 리랭커 학습 라벨, 사후 보정에 쓰인 데이터 라벨이 확률을 바꿉니다. 따라서 “별도 조정 없이 보정돼 있다”는 표현에도 어떤 관련성을 기준으로 했는지 묻는 것이 필요합니다. 순서만 이용할 때는 점수의 절대값이 직접 필요하지 않지만, 임계값이나 개수 추정에는 중요해집니다.

**Limitations.** 원문이 명시한 범위는 다음과 같습니다. 공개 모델들은 목적함수뿐 아니라 학습 데이터도 다르므로 결과는 당시 사용 가능한 판단 학습의 비교이며 RLCD 자체의 판정은 아닙니다. 자체 리랭커는 9B·27B를 한 가지 학습법으로 한 번씩 학습했고 하이퍼파라미터 탐색을 하지 않았습니다. 보정은 TREC DL, 관련성 등급 한 기준, 임계값 하나에서 측정했습니다. 질문 문구는 개발 데이터로 고르지 않았고 대안도 하나만 시험했습니다. 평가 시점의 판단 모델들은 공개된 지 최대 한 달 정도여서 이후 버전이 결과를 바꿀 수 있습니다.

저자들은 비교를 반복할 수 있도록 모델별 원시 확률 출력과 코드를 공개한다고 밝힙니다. 이 리뷰는 공개 링크와 원문의 재현성 설명을 확인했으며, 모델을 다시 학습하거나 실험을 재실행하지는 않았습니다. [원문 7절](https://arxiv.org/html/2610.32318v1#S7)

### 📖 **Chapter 8: Conclusion**

결론은 두 연구 질문을 합칩니다. 같은 기반에서 9B 이하의 전용 리랭킹 학습이 판단 학습보다 순위를 잘 매기고, 27B에서는 비슷합니다. 판단 모델의 확률 보정 우위는 질문 문구에 달려 있으며, 작은 모델의 순위 열세를 임계값 선택에서 자동으로 만회하지는 못합니다. 저자들이 내리는 실용적 결론은 리랭커가 필요하면 리랭킹 작업에 맞춰 학습하라는 것입니다.

## 실험 결과 심층 분석

이 논문에서 가장 설득력 있는 비교는 같은 기반 모델의 일반 채팅·판단·전용 리랭킹 세 상태입니다. 0.6B와 0.8B에서는 전용 학습의 이득이 크고, 9B에서는 간격이 좁아지며, 27B에서는 비슷해집니다. 다만 여섯 기반 모델의 계열·학습 방식까지 모두 같지는 않으므로, 이 결과를 모델 크기 하나의 효과로 분해한 실험으로 읽어서는 안 됩니다.

통계적 근거도 구분해야 합니다. 순위 비교는 질문별 대응 t 검정, 열 컬렉션 Holm 보정, 유의수준 0.05를 사용했습니다. 저자들이 제시한 48/60이라는 집계는 이 순위 비교에 대한 것입니다. 보정 지표와 필터 F1, 개수 오차 전체에도 같은 유의성이 입증됐다는 뜻은 아닙니다. 해당 보정·활용 결과의 신뢰구간과 별도 유의성 검정은 논문에 보고되지 않았습니다.

또한 Table 1은 순위가 좋은 판단 모드를, Table 3은 보정이 좋은 판단 모드를 중심으로 읽어야 합니다. Kev-8B의 전체 평균 순위 51.7은 isolated인데 ECE 0.113은 joint입니다. 두 숫자를 한 모드의 성능으로 합치면 논문에 없는 시스템이 됩니다. 27B의 경우처럼 순위가 비슷한 상황에서 보정이 실제 선택에 도움이 되는 사례도 함께 봐야 합니다.

문구 실험과 Platt scaling 실험은 데이터 라벨의 의미를 확인하는 데 유용합니다. 비슷한 문장처럼 보여도 “답을 포함한다”와 “관련 정보를 포함한다”는 서로 다른 사건입니다. 보정 데이터에서 관련 문서가 드문지 흔한지도 확률을 바꿉니다. RAG에서 확률 0.5로 문서를 자르려면, 검색 순위 평가와 별도로 그 기준이 실제 자료에서 어떤 문서를 남기는지 확인해야 한다는 것이 이 결과를 읽은 리뷰어의 해석입니다.

## 기술적 함의와 응용

검색 시스템을 고를 때 이 연구가 던지는 질문은 구체적입니다. 필요한 것이 상위 몇 개의 순서라면 nDCG처럼 순위 지표를 봐야 하고, 문서를 자동으로 버리거나 개수를 추정한다면 확률의 의미도 확인해야 합니다. 모델이 확률을 출력한다는 형식만으로 두 요구를 모두 충족하지는 않습니다.

판단 모델을 리랭커로 사용하는 것은 가능합니다. Jev와 Kev-27B는 이 실험에서도 강한 순위를 보였습니다. 다만 그 성능이 판단 학습의 고유 효과인지는 같은 기반 모델의 전용 학습·일반 모델과 비교해야 합니다. 이 논문의 핵심은 특정 출력 형식의 유행보다 **같은 조건의 비교, 정답의 정의, 점수를 사용하는 방법**을 먼저 살피는 데 있습니다.
