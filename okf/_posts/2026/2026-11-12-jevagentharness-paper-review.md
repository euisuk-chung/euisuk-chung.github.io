## 논문 개요와 전체 구조

고객 지원 에이전트는 주문 번호를 조회하고, 누락된 정보를 묻고, 취소 API를 호출할 수 있습니다. 하네스는 이처럼 모델에 도구를 건네고, 실행 결과를 다음 단계에 돌려주는 프로그램입니다. JevAgentHarness는 하네스가 후보를 열거할 수 있는 단계에 별도의 **결정 모델**을 배치합니다. 결정 모델은 후보별 확률을 반환하고, 하네스는 해당 결정에 맞춰 정한 임계값으로 결과를 받아들일지 판단합니다. 주문을 조회할지 묻는 문제와 취소 사유를 고객에게 설명하는 문제에 서로 다른 호출 경로가 생깁니다. [원문 서론과 예시](https://arxiv.org/html/2610.21412v1#S1)

Kunlun Zhu 외 7명의 2026년 10월 15일 제출본(arXiv v1)을 다룹니다. 원문은 **§1–2**에서 문제와 위임 방식을 정의한 뒤 **§3–5**에서 벤치마크, 하네스, 4B 모델을 제시합니다. **§6–9**는 실험 계획, 결과, 관련 연구, 결론으로 이어지며 한계, 윤리, 참고문헌이 뒤따릅니다. 부록 A–I는 이론, 벤치마크, 구현, 학습, 통계, 비용, 세부 결과, 관련 연구, 실행 궤적을 같은 순서로 보충합니다. [서지와 버전](https://arxiv.org/abs/2610.21412v1) · [부록 목차](https://arxiv.org/html/2610.21412v1#Ax1)

## 핵심 기여와 혁신성

- **같은 모델을 세 가지 평가에서 비교합니다.** 독립 문항, 기록한 상태에서의 선택, 실행 중인 에이전트의 최종 성공률을 순서대로 측정합니다. 오류가 뒤의 상태까지 바꾸는 효과는 마지막 평가에서 드러납니다. [§3](https://arxiv.org/html/2610.21412v1#S3)
- **결정마다 위임 범위를 설정합니다.** 도구 선택과 인수 선택을 나누고, 각 지점의 실제 실행 기록에서 추정한 정답률과 오류 비용을 기준으로 임계값을 구합니다. 확신도가 낮거나 값을 자유 텍스트로 만들어야 하면 LLM에 맡깁니다. [§2.1](https://arxiv.org/html/2610.21412v1#S2.SS1) · [§4](https://arxiv.org/html/2610.21412v1#S4)
- **정상 경로와 오류 뒤에 생기는 상태를 함께 학습합니다.** 교사의 분포와 환경 정답으로 4B 모델을 후학습합니다. 실험은 이 지도학습의 효과와 루프 안에서 추가로 수행한 강화학습의 효과를 따로 비교합니다. [§5](https://arxiv.org/html/2610.21412v1#S5) · [Table 3](https://arxiv.org/html/2610.21412v1#S7.T3)

## 기술적 세부사항

결정 지점 $`d`$는 반복해서 등장하는 선택의 종류, 상태 $`s`$는 현재까지의 요청과 관측, $`O_d(s)`$는 하네스가 그 상태에서 열거한 후보입니다. 결정 모델은 $`p(o\mid s)`$를 반환하고, 최고 확률 후보 $`\hat o`$의 확률을 확신도 $`c(s)=p(\hat o\mid s)`$로 사용합니다. Cascade 모드에서는 이 값이 지점별 임계값 $`\tau_d`$ 이상일 때만 답을 받아들입니다. [§2](https://arxiv.org/html/2610.21412v1#S2)

![도구 또는 인수 후보를 점수화하고 결정 지점별 확신도 임계값에 따라 결정 모델의 답을 채택하거나 LLM에 넘기는 흐름]({{ '/img/reviews/2026/jevagentharness-paper-review/confidence-routing.svg' | relative_url }})

*리뷰어 작성 도식. 원문의 Cascade 정의와 도구·인수 위임 절차를 바탕으로 그렸습니다. 자유 텍스트 인수는 LLM이 작성합니다. 도구가 이미 정해졌다면 위임하지 못한 인수를 한 번의 LLM 호출로 채울 수 있습니다.* [원문 Figure 3](https://arxiv.org/html/2610.21412v1#S1.F3) · [원문 Figure 8과 구현 설명](https://arxiv.org/html/2610.21412v1#A3)

부록 A는 지점별 설정을 묶은 위임 구성 $`\phi`$의 목표를 에피소드당 기대 비용 $`C`$와 성공률 $`S`$로 표현합니다. $`\phi_\varnothing`$는 LLM 단독 구성, $`\delta`$는 허용하는 성공률 하락 폭입니다. 예를 들어 DecisionGym의 실험은 3퍼센트포인트를 비열등성 한계로 둡니다. [부록 A](https://arxiv.org/html/2610.21412v1#A1) · [§6](https://arxiv.org/html/2610.21412v1#S6)

```math
\min_{\phi} C(\phi)
\qquad \text{subject to} \qquad
S(\phi)\ge S(\phi_\varnothing)-\delta .
```

특정 결정의 채택 조건은 비용을 두 갈래로 비교해 얻습니다. $`g_d(c)`$는 결정 모델이 확신도 $`c`$를 낸 사례 중 실제 정답 비율, $`q_L(c)`$는 그 사례에서 LLM이 맞히는 비율입니다. $`V`$는 오판의 비용이고 $`\Delta C`$는 LLM 호출을 생략할 때 절감하는 비용입니다. 이미 결정 모델을 호출했다면 그 질의 비용은 양쪽에 공통입니다. 채택 시 기대 오류 비용 $`(1-g_d(c))V`$와, 넘길 때 기대 비용 $`(1-q_L(c))V+\Delta C`$를 비교하면 식 (3)이 됩니다. $`g_d(c)=c`$이고 LLM의 정답률이 $`c`$와 무관하다는 가정 아래 식 (4)의 단일 임계값이 나옵니다. 오류의 비용이 커질수록 같은 절감액이 허용하는 정확도 격차는 작아집니다. [부록 A 식 (3)–(4)](https://arxiv.org/html/2610.21412v1#A1)

```math
g_d(c)-q_L(c)\ge -\frac{\Delta C}{V},
\qquad
\tau^\star=\max\!\left(0,\ q_L-\frac{\Delta C}{V}\right).
```

## 챕터별 상세 리뷰

### 📖 **Chapter 1: Introduction**

저자들은 코딩, 컴퓨터 조작, 고객 지원에서 여러 번 호출하는 LLM이 장시간 작업의 비용과 지연을 만든다는 문제로 시작합니다. 하네스는 도구 이름과 실행 가능한 행동을 이미 알고 있으므로, 결정 모델에 요청·이력·질문·선택지를 함께 전달할 수 있습니다. Figure 1의 주문 취소는 조회, 취소, 추가 질문이라는 후보를 보여 줍니다. 논문에 기록된 한 에피소드에서 Jev 호출은 LLM 호출 시간의 28%, 가격의 2.6%였습니다. 이는 해당 궤적의 호출 단위 비교입니다. [§1 및 Figure 1](https://arxiv.org/html/2610.21412v1#S1)

고정된 객관식 데이터에서는 모델이 실수해도 다음 문항이 달라지지 않습니다. 실행 중인 에이전트에서는 잘못 취소한 주문이 환경을 바꾸고, 엉뚱한 조회는 다음 관측을 바꿉니다. 다음 단계에 어느 모델을 넣을지는 이 차이를 포함한 평가가 필요합니다. 저자들은 Figure 2에서 세 수준의 평가, 확신도에 따른 위임, 에이전트가 방문한 상태의 후학습을 하나의 실험 순서로 묶습니다. Stage 1에서 위임을 개별 평가하고, Stage 2에서 뽑힌 구성의 조합을 새 작업에서 평가합니다. [Figure 2](https://arxiv.org/html/2610.21412v1#S1.F2)

### 📖 **Chapter 2: Where and How to Delegate**

논문은 행동에 직접 관여하는 세 지점으로 **도구, 도구 인수, 도구가 없는 환경의 다음 행동**을 듭니다. 루프를 제어하는 다섯 지점은 **메모리 쓰기, 메모리 읽기, 실패 뒤 반성, 종료, 저렴한 LLM으로의 라우팅**입니다. 같은 도구 선택 지점에도 아래와 같이 서로 다른 책임 배치가 가능합니다. Table 4는 Stage 1 구성과 후속 탐색 구성을 구분합니다. [Figure 3](https://arxiv.org/html/2610.21412v1#S1.F3) · [Table 4](https://arxiv.org/html/2610.21412v1#A1.T4)

| 모드 | 결정 모델과 LLM의 역할 |
| --- | --- |
| Replace | 결정 모델이 항상 후보를 선택합니다. |
| Cascade | 결정 모델이 먼저 답하고, 확신도가 임계값에 못 미치면 LLM이 선택합니다. |
| Assist | 결정 모델이 후보 목록을 좁히고, LLM이 최종 선택합니다. |
| Guard | LLM이 제안하고, 결정 모델이 승인 또는 거부합니다. |
| Trigger | 결정 모델이 반성 같은 선택적 모듈을 실행할지 정합니다. |

주문 취소 예시에서 세 번째 단계의 Jev는 고객에게 질문할 확률 0.63, 취소할 확률 0.37을 반환했습니다. LLM이 결정권을 받아 고객에게 질문했습니다. 다음 단계에서는 결정 모델이 취소 도구를 채택할 만큼 확신했고, 대화에 나온 주문과 열거된 사유를 인수로 골랐습니다. 도구 자체의 선택과 각 인수의 채택 여부를 따로 결정하는 사례입니다. [§2 예시](https://arxiv.org/html/2610.21412v1#S2) · [부록 B Figure 6](https://arxiv.org/html/2610.21412v1#A2.SS1)

§2.1의 임계값은 에이전트 LLM당 150개의 별도 보정 작업에서 얻습니다. LLM이 실제로 행동하는 동안 결정 모델은 답만 기록하는 **섀도 모드**로 동작합니다. 연구진은 확신도 순서대로 최소 20개씩 구간을 만들고, 그 구간부터 더 높은 모든 구간의 추정 이점이 0 이상인 최저 확신도를 택합니다. 오판 비용은 해당 지점에서 모두 맞힌 에피소드와 한 번 틀린 에피소드의 성공률 차이를 바탕으로 추정하고, 성공한 작업 하나를 1달러로 평가합니다. 조건을 충족하는 구간이 없으면 해당 결정 지점을 LLM에 맡깁니다. Jev와 Flash의 보정값은 도구 1.00, 인수 0.99였습니다. [§2.1](https://arxiv.org/html/2610.21412v1#S2.SS1) · [부록 A](https://arxiv.org/html/2610.21412v1#A1)

### 📖 **Chapter 3: AgentDecisionBench**

L1은 독립 문항입니다. BFCL v4의 도구 선택 1,114개와 인수 1,949개, When2Call 928개를 객관식으로 변환합니다. L2는 기록된 실행의 중간 상태를 모델들이 공통으로 읽는 평가입니다. 예를 들어 DecisionGym의 새 작업 200개에서 나온 공통 도구 선택 상태 5,314개를 동일하게 제시합니다. 결정 모델의 답은 채점되지만 궤적에는 적용되지 않습니다. L3에서는 결정 모델이 실제 도구 선택을 모두 맡고 LLM이 인수를 작성합니다. ALFWorld에서는 결정 모델이 모든 행동을 선택합니다. 최종 성공률은 현재 선택이 다음 관측을 바꾸는 조건에서 얻습니다. [§3](https://arxiv.org/html/2610.21412v1#S3) · [부록 B.1과 B.5](https://arxiv.org/html/2610.21412v1#A2)

DecisionGym은 가상 상점의 고객, 주문, 재고와 작업 계획을 시드로 생성합니다. 기본 평가의 후보는 68개 도구와 종료 옵션입니다. 핵심 7개, 질문 1개, 핵심 도구를 닮은 31개, 무관한 29개가 섞여 있습니다. 여러 행동이 유효한 상태에서는 남은 계획을 진전시키는 선택을 정답으로 인정합니다. 사용자에게 물어야만 진행할 수 있는 상태를 **must-ask**라고 부릅니다. Strict 모드에서는 계획에 없는 데이터 변경이 실행을 즉시 종료합니다. 학습·보정·평가 시드를 분리하고 환경의 답안은 모델 입력에 넣지 않습니다. [§3 DecisionGym](https://arxiv.org/html/2610.21412v1#S3) · [부록 B.5](https://arxiv.org/html/2610.21412v1#A2.SS5)

공개 환경도 함께 씁니다. 논문 자체 루프는 τ²-bench, ALFWorld, DecisionGym을 다루고, 기존 하네스의 훅을 이용해 SWE-bench Verified와 터미널 작업도 시험합니다. 추가로 **Shift**는 도구 이름, 요청 표현, 작업 형태를 바꿔 학습 분포 밖의 일반화를 보고, **Hard**는 여러 고객을 처리하면서 학습에서 보지 못한 취소·배송 규칙까지 따르게 합니다. 두 조건은 원래의 등록 실험에 이어 추가한 평가입니다. [§3](https://arxiv.org/html/2610.21412v1#S3) · [부록 D.6](https://arxiv.org/html/2610.21412v1#A4.SS6) · [부록 G.9](https://arxiv.org/html/2610.21412v1#A7.SS9)

### 📖 **Chapter 4: JevAgentHarness**

하네스는 상태를 텍스트로 바꾸고 열거형·예/아니오·문맥에서 복사할 값을 타입이 있는 질문으로 만듭니다. 도구 선택이 임계값에 미달하면 LLM이 전체 도구 호출을 작성합니다. 도구를 채택한 경우 각 인수의 임계값을 따로 확인하고, 확신도가 낮거나 자유 텍스트인 인수는 이미 정해진 도구를 대상으로 한 번의 LLM 호출에서 채웁니다. 원문은 기준 모델, 결정 모델, 작업 규칙이 바뀌면 임계값도 다시 적합시킵니다. [§4](https://arxiv.org/html/2610.21412v1#S4) · [부록 C](https://arxiv.org/html/2610.21412v1#A3)

어댑터가 가능한 위임의 범위를 정하기도 합니다. 예컨대 mini-SWE-agent에서는 다음 응답을 강한 LLM과 빠른 LLM 중 어디에 요청할지 고르고, pi에서는 훅으로 guard나 trigger를 실행할 수 있습니다. LLM을 호출하기 전에 다음 행동을 반환할 수 있는 훅이 있어야 Replace나 Cascade를 그대로 적용할 수 있습니다. 결정 모델이나 어댑터가 실패하면 기존 실행 경로로 돌아갑니다. ### 📖 **Chapter 5: AgentDecision-4B**

연구진은 Qwen3-4B에 저랭크 어댑터(LoRA)를 붙이고 지도 미세조정(SFT)을 먼저 진행합니다. 587개 학습 작업에서 기록한 15,694개 상태 중 30.9%는 스크립트가 개발 중 관찰된 종류의 실수를 재현한 뒤의 상태입니다. 환경 정답 $`a^\star`$를 Jev도 1순위로 두었을 때, 목표 분포 $`y_a`$에는 정답 원-핫 0.3과 Jev 확률 분포 0.7을 섞습니다. Jev의 1순위가 틀리면 환경의 정답 원-핫만 사용합니다. [§5](https://arxiv.org/html/2610.21412v1#S5) · [부록 D.1–D.2](https://arxiv.org/html/2610.21412v1#A4)

```math
\mathcal L_{\mathrm{SFT}}
=\mathbb E_s\sum_a
\left[-y_a\log p_a+\mu(p_a-y_a)^2\right],
\qquad \mu=0.5.
```

식 (1)에서 $`p_a`$는 학생 모델이 상태 $`s`$에서 후보 $`a`$에 준 확률입니다. 첫 항은 목표 분포의 확률 질량을 배운 교차 엔트로피이며, 둘째 항은 출력 확률을 목표 확률과 맞추는 Brier 형태의 제곱 오차입니다. 논문 설정은 LoRA 랭크 32, 2 epoch, 학습률 $`10^{-4}`$입니다. 제곱 오차 항의 단독 효과는 별도로 분리하지 않았습니다. [§5 식 (1)](https://arxiv.org/html/2610.21412v1#S5) · [부록 D.1](https://arxiv.org/html/2610.21412v1#A4.SS1)

이후 강화학습은 SFT 모델이 실제 결정을 내려 만든 궤적에서 진행합니다. 작업당 8개의 에피소드를 생성하고, 같은 작업의 보상 평균과 표준편차로 각 에피소드의 상대 이점을 계산하는 GRPO를 사용합니다. $`S_i`$는 작업 성공 여부, $`N_i`$는 LLM 호출 횟수, $`E_i`$는 되돌릴 수 없는 오판 여부입니다. 식 (2)의 호출 페널티는 $`N_0=10`$에서 포화되며, $`\lambda=0.5`$이므로 성공 보상 항이 절반이 됩니다. 비가역 오판은 $`\eta=0.2`$를 별도로 차감합니다. [§5 식 (2)](https://arxiv.org/html/2610.21412v1#S5)

```math
R_i=S_i\left(1-\lambda\min\!\left(1,\frac{N_i}{N_0}\right)\right)-\eta E_i .
```

각 에피소드의 결정들은 공통 이점을 받고, 그룹에서 재등장한 상태에는 단계 수준 항도 더합니다. SFT 모델과 지나치게 멀어지지 않도록 선택지 분포에 KL 페널티를 둡니다. Flash-Lite를 고정 LLM으로 두고 15번째 반복의 모델을 Stage 2의 AgentDecision-4B v1으로 고정합니다. 이후 공개 도구 사용 데이터로 추가 학습한 체크포인트와는 구분합니다. [§5](https://arxiv.org/html/2610.21412v1#S5) · [부록 D.2와 D.9](https://arxiv.org/html/2610.21412v1#A4)

### 📖 **Chapter 6: Experimental Protocol**

Stage 1은 한 번에 위임 하나를 켜고, 같은 작업의 LLM 단독 실행과 성공·비용을 비교합니다. 성공률 차이는 **비열등성**으로 평가합니다. 이는 LLM보다 사전에 정한 한계만큼 또는 그 이상 나쁘다는 귀무가설을 기각하는 검정입니다. DecisionGym 한계는 3퍼센트포인트, τ²-bench는 5퍼센트포인트입니다. Stage 1의 11개 검정에 Holm 보정을 적용해 가족별 오류율을 5%로 통제합니다. 일부 위임은 Jev와 Intern-Decision-4B 모두가 조건을 통과해야 등록된 주장이 성립하도록 설계했습니다. [§6](https://arxiv.org/html/2610.21412v1#S6) · [부록 E와 Table 25](https://arxiv.org/html/2610.21412v1#A5)

Stage 2는 Stage 1 결과를 읽기 전에 선정 규칙과 검정 계획을 등록했습니다. 결정 지점별로 위임이 실제 발생하고 더 저렴하며 비열등성 기준을 충족한 구성을 고릅니다. 최대 절감률과 2포인트 안에 든 후보가 여럿이면 LLM에 더 많이 남기는 쪽을 택합니다. 통과한 구성을 묶어 새 DecisionGym 작업 500개에서 LLM 단독 및 가장 좋은 단일 위임과 비교하고, Jev를 자체 학습한 4B로 바꾼 조건도 평가합니다. 선택지 정확도 검정은 동일하게 기록한 상태에서, 작업 성공률 검정은 각 구성의 실제 실행에서 수행합니다. [§6](https://arxiv.org/html/2610.21412v1#S6) · [부록 E](https://arxiv.org/html/2610.21412v1#A5)

#### 7.4 RQ4: Can a 4B model learn the decisions?

Qwen3-4B에 실행 상태를 지도학습시키자 Shift의 기록 상태 정확도가 52.9%에서 98.4%, 모든 도구를 선택하는 Shift 실제 작업 성공률이 13.5%에서 96.0%로 올랐습니다. SFT는 2.2 GPU·시간을 썼고, 이어 적용한 GRPO는 4.5 GPU·시간과 LLM 비용 26.53달러를 추가했습니다. #### 7.5 Where delegation fails

첫째, 높은 확신도의 잘못된 취소나 환불처럼 상태를 되돌릴 수 없는 결정은 한 번으로 작업을 끝낼 수 있습니다. 저자들이 추적한 Jev의 실패 34건은 모두 첫 비가역 도구 오판으로 끝났습니다. 둘째, 새로운 규칙은 익숙한 상태에서 얻은 확신도를 무력화할 수 있습니다. 고객 10명의 Hard 조건에서 새 규칙을 학습하지 않은 4B 모델이 들어간 에이전트는 LLM 단독 88.0%와 비교해 3.0%만 해결했습니다. 해당 규칙으로 재학습한 모델의 보류 상태 정확도는 76.5%에서 95.3%로 올랐습니다. 전자는 에피소드 성공률, 후자는 취소·배송 상태의 선택 정확도입니다. 셋째, LLM 호출을 그대로 남겨 두는 Guard는 추가 판단을 호출하는 만큼 절감 여지가 줄어듭니다. ### 📖 **Chapter A: Delegation Theory**

A는 최종 성공률 제약과 에피소드 비용 최소화라는 목표를 먼저 두고, 다섯 통합 모드를 수식으로 정의합니다. Cascade는 확신도 구간별로 두 모델의 오류 비용을 비교합니다. Trigger와 Guard에서는 행동이 필요할 때 얻는 이익, 불필요할 때 생기는 손해, 호출 비용을 함께 봅니다. 실행 빈도가 같은 무작위 트리거와 비교할 때, 참 양성률과 거짓 양성률의 차이 $`J=\mathrm{TPR}-\mathrm{FPR}`$가 이득을 설명하는 양으로 등장합니다. 항상 실행하지 않는 정책은 필요 상태가 드물면 표면적인 정확도가 높아도 $`J=0`$입니다. 부록의 사전 가설 검토는 고정값과의 비교, 온도 보정, 구성 우위가 각각 같은 결론을 내지 않았음을 보여 줍니다. ## 기술적 함의와 응용

도구 이름이 열거 가능한 고객 지원 시스템에서는 한 호출을 도구 선택과 인수 선택으로 쪼개 각각 다른 위임률을 적용할 수 있습니다. 명령의 내용이 자유 텍스트인 코딩 환경에서는 비슷한 장치를 모델 라우팅에 쓸 수 있지만, 논문의 비용 이득은 작았습니다. 두 예의 차이는 후보를 직접 만들고 검증할 수 있는 단계가 어디까지인가에 있습니다. [§4](https://arxiv.org/html/2610.21412v1#S4) · [부록 C](https://arxiv.org/html/2610.21412v1#A3)
