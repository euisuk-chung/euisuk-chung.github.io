## 논문 개요와 전체 구조

추론 모델에게 “생각하는 동안 특정 단어를 쓰지 마세요”라고 요청했는데도 모델이 그 단어를 계속 사용한다면, 모델에게 그런 능력이 없다고 판단해도 될까요? 이 논문은 **모델이 할 수 있는 일과, 평가 프롬프트가 실제로 끌어낸 일을 구분해야 한다**고 주장합니다. 사용자 메시지에만 제약을 넣는 기존 평가와 달리, 모델의 사고사슬(Chain of Thought, CoT) 안에 자기 지시를 두면 같은 모델의 텍스트 제약 준수율이 크게 달라집니다.

Uriel Dolev, Idan Schwartz, Yoav Goldberg는 이를 **Self-Instructed CoT Controllability**라고 부릅니다. 추가 학습 없이 추론의 시작 부분을 미리 채우는 *reasoning prefill*, 또는 사용자 프롬프트가 모델에게 자기 지시를 먼저 쓰게 하는 *bootstrap*을 비교합니다. 실험은 공개 가중치 모델 5개, QA·에이전트 벤치마크 5종, 텍스트 제약 9종을 중심으로 구성되며, 폐쇄형 모델·다중 턴·CoT 모니터 평가로 이어집니다.

이 글은 2026년 10월 16일 제출된 [arXiv 2610.23257v1](https://arxiv.org/abs/2610.23257v1)의 26쪽 PDF를 기준으로 합니다. 아래의 ‘제어’는 주로 **관찰 가능한 추론 텍스트의 형식과 내용에 대한 제약 준수**입니다. 모델의 숨은 내부 계산이나 문제 해결 전략을 자유롭게 바꾼다는 뜻은 아닙니다. 이 구분은 저자가 직접 명시한 한계이기도 합니다.

## 핵심 기여와 혁신성

**문제의 중요성**은 하나의 능력이 활용성과 감독에 서로 다른 의미를 갖는 데 있습니다. 추론을 지정한 언어·형식으로 작성할 수 있으면 사용하기 쉬워집니다. 동시에 모델이 어떤 내용을 CoT에 드러낼지 조절할 수 있다면, CoT를 읽는 모니터의 판단도 달라질 수 있습니다. 논문은 어느 한쪽만으로 제어 가능성을 평가하지 않습니다.

**기존 접근의 한계에 대한 저자의 해석**은 “제약을 못 따른다”와 “사용자 메시지의 CoT 제약을 우선하지 않는다”가 혼동되었을 수 있다는 것입니다. 검증 가능한 최종 보상으로 추론 모델을 학습하는 RLVR이 CoT 텍스트 자체의 지시 준수를 직접 보상하지 않는다는 점을 배경으로 제시합니다. 이것은 학습 메커니즘을 인과적으로 입증한 결과라기보다, 새로운 실험을 설계하게 한 가설입니다.

**해결책의 독창성**은 제약을 전달하는 위치와 생성 주체를 분리한 데 있습니다. 같은 과제·제약·채점기를 유지하면서, 사용자 메시지·미리 채운 자기 지시·모델이 스스로 생성한 자기 지시를 비교합니다. 구체적인 제약을 되풀이하지 않는 일반적인 상기 문장도 시험하여, 단순한 문체 모방 외에 지시를 상기시키는 효과를 살핍니다.

**핵심 결과**로 DeepSeek-R1의 평균 준수율은 0.4%에서 22.2%, Qwen3-32B는 2.5%에서 34.3%로 높아집니다. 그러나 여전히 모든 제약을 안정적으로 만족하는 수준은 아닙니다. 또한 이는 **문제 정답률의 증가가 아닌 CoT 제약 준수율의 증가**입니다. 이 논문을 읽을 가치는 높은 수치 자체보다, 능력 평가가 유도 방식과 측정 단위에 얼마나 민감한지 확인하는 데 있습니다. [원문 1·3.1절, PDF 1–5쪽](https://arxiv.org/pdf/2610.23257v1#page=2)

## 기술적 세부사항

### 무엇을 바꾸고 무엇을 고정하는가

과제는 그대로 두고, CoT에 요구하는 조건과 그 전달 경로를 바꿉니다. *Constraint-specific* 자기 지시는 “이 단어를 피하면서 풀겠다”처럼 조건을 직접 적습니다. *Generic* 자기 지시는 “사용자의 제약을 따르며 풀겠다”처럼 이미 주어진 조건을 상기시킵니다. 전자는 제약 자체를 포함하지만 후자는 사용자 메시지에 제약이 있어야 의미가 있습니다.

![사용자 지시, reasoning prefill, bootstrap을 비교한 Self-Instructed CoT의 입력과 생성 경계]({{ '/img/reviews/2026/self-instructed-cot-review/figure-02-methods.png' | relative_url }})

*원문 Figure 2, PDF 3쪽. 실선 상자는 입력, 점선 상자는 모델이 생성한 부분입니다. 그림 영역만 크롭했으며 내용은 번역·재배열하지 않았습니다. Uriel Dolev 외, CC BY 4.0. [고정 버전 원문](https://arxiv.org/pdf/2610.23257v1#page=3).*

Reasoning prefill은 모델이 이어 쓸 추론의 첫 부분을 평가자가 제공하는 방식입니다. Bootstrap은 그 문장을 추론 첫머리에 쓰도록 **사용자 메시지로 요청**하며, 실제 문장은 모델이 생성합니다. 두 방식 모두 추가 가중치 학습을 하지 않지만, reasoning 채널에 접근해야 하는지는 다릅니다. 이 논문의 실험 결과를 모든 API가 동일한 prefill 기능을 제공한다는 제품 설명으로 읽으면 안 됩니다.

### 정답률·준수율·echo를 구분하는 방법

모델이 자기 지시를 정확히 반복한 비율인 *echo rate*는 뒤의 추론이 제약을 지킨 비율과 다릅니다. 채점할 때는 **미리 채워 넣었거나 첫머리에 반복한 자기 지시를 제외하고, 그 뒤의 모델 생성 continuation만 평가**합니다. SWE-bench에서는 여러 턴의 CoT를 모아서 하나의 추론 기록처럼 채점합니다.

원문 Appendix A.4는 데이터셋–제약 조합을 셀로 두고 다음과 같이 평균 점수와 표준오차를 계산합니다.

```math
\mathrm{score}=\frac{1}{K}\sum_{c=1}^{K}p_c
```

$`K`$는 데이터셋–제약 셀의 개수이며, $`p_c`$는 셀 $`c`$에서 조건을 만족한 CoT의 비율입니다. 셀마다 동일한 가중치를 주므로, 문제 수가 많은 벤치마크가 전체 결과를 독점하지 않습니다. $`p_c`$를 0–1 비율로 넣으면 식의 결과도 0–1이고, 논문의 백분율 표시는 여기에 100을 곱한 값입니다. 따라서 전체 생성 기록을 한꺼번에 합친 단순 성공 비율과는 집계 방식이 다릅니다.

```math
\mathrm{SE}=\frac{1}{K}\sqrt{\sum_{c=1}^{K}\frac{p_c(1-p_c)}{n_c}}
```

$`n_c`$는 셀별 CoT 수이고, $`p_c(1-p_c)/n_c`$는 베르누이 비율 추정의 분산 항입니다. 저자는 **CoT들을 독립 베르누이 시행으로 취급**해 이 식을 사용합니다. SE는 점수의 추정 불확실성이지, 두 조건 차이의 유의성을 자동으로 보장하는 값은 아닙니다. 원문은 별도의 비교에서 McNemar 검정과 paired bootstrap도 사용하므로, 각 결과에 맞는 검정 맥락을 따로 읽어야 합니다. [Appendix A.4, PDF 12쪽](https://arxiv.org/pdf/2610.23257v1#page=12)

## 챕터별 상세 리뷰

### 📖 **Chapter 1: Introduction**

**챕터의 위치와 역할**: 최종 출력에 대한 지시 준수 연구에서 출발해, 추론 텍스트 자체를 제어하는 문제로 초점을 옮깁니다. 사용자 편의와 감독의 이해관계가 왜 다를 수 있는지 먼저 정리합니다.

**저자의 서술 순서를 따른 상세 내용:**

1. **최종 출력과 CoT의 학습 차이**: 일반적인 instruction following은 답변이 사용자의 요구에 맞는지 학습합니다. 반면 추론 모델은 최종 출력의 검증 가능한 보상으로 학습되므로, 최종 답변에서 가능한 형식 제어가 CoT에서도 같은 수준으로 나타난다고 단정할 수 없습니다.
2. **서로 다른 두 동기**: 활용 측면에서는 구조·언어·표현을 제어하는 것이 유리합니다. 감독 측면에서는 모델이 계획이나 의도를 임의로 감출 수 없을 때 CoT 모니터가 더 많은 정보를 얻을 수 있습니다. 이 두 관점 때문에 ‘높은 controllability’가 무조건 좋거나 나쁘다는 단일 판단은 성립하지 않습니다.
3. **기존 평가의 재해석**: 저자는 사용자 메시지에서 제약을 잘 따르지 않는 것이 능력 부재보다 지시의 우선순위 문제일 가능성을 제기합니다. Figure 1은 특정 단어를 피해야 하는 수학 문제에서 이 차이를 직관적으로 보여줍니다. 같은 문제를 맞혀도 CoT의 표현 제약은 한 조건에서 실패하고 다른 조건에서 성공할 수 있습니다.
4. **새 평가의 네 가지 관찰**: 자기 지시는 준수율을 높이고, 일반적인 상기 문장도 도움이 되며, bootstrap으로 reasoning prefill 없이도 효과를 얻고, 모니터 실험에서 탐지율이 달라집니다. 논문은 이 결과를 기존 평가를 폐기할 근거보다 **상보적인 평가를 추가할 근거**로 제시합니다.

**챕터의 핵심 기여**: 낮은 관측 점수를 곧바로 능력의 상한으로 해석하지 않도록 평가 질문을 다시 설정합니다.

**다음 챕터로의 연결**: 이러한 해석이 단순 프롬프트 사례에 머물지 않도록, 동일한 과제와 채점기를 사용한 평가 설계를 정의합니다. [1절, PDF 1–2쪽](https://arxiv.org/pdf/2610.23257v1#page=1)

### 📖 **Chapter 2: Self-Instructed CoT Controllability**

**챕터의 위치와 역할**: 무엇을 제어하고, 어떤 입력을 바꾸며, 성공을 어떤 단위로 측정하는지 명확히 합니다.

**저자의 서술 순서를 따른 상세 내용:**

1. **2.1 Data — 다섯 벤치마크와 아홉 제약**: QA는 GPQA·HLE·MMLU-Pro의 객관식 문제, Agent는 BFCL의 도구 호출과 SWE-bench Verified의 다중 턴 코딩 과제입니다. 원래 과제는 QA 1,214개와 Agent 350개이며, 각각 9개 제약과 짝지어 **10,926개 QA + 3,150개 Agent = 14,076개 과제–제약 조합**을 만듭니다. 14,076개가 모두 서로 다른 원래 질문이라는 뜻은 아닙니다.
2. **제약의 세 범주**: 정보 억제는 단일 단어·여러 단어와 그 동의어를 피하기, 질문과 무관한 내용을 생각하기입니다. 정보 추가는 추론의 시작·끝에 지정 문장을 붙이기, 문장을 특정 단어로 끝내기, 단어 사이마다 `meow`를 넣기입니다. 문체 변경은 소문자·대문자·교대 대소문자입니다. 억제할 단어는 각 과제를 풀 때 모델이 자주 사용하는 단어를 선택합니다.
3. **2.2 Self-Instruction — 자기 지시의 설계**: DeepSeek-R1과 Qwen3에는 대화체, GPT-OSS에는 짧고 선언적인 문장을 사용합니다. 표면 형식을 요구하는 다섯 제약에서는 자기 지시 자체도 해당 형식으로 작성합니다. 시작부터 제약을 위반하는 시범을 주지 않으려는 설계이며, 효과는 부록 C에서 따로 분해합니다.
4. **2.3 Elicitation Methods — 여섯 조건**: 아래 표는 원문의 순서대로 어떤 경로에 제약이 있는지 정리한 것입니다. Generic prefill만 단독으로 사용하는 조건은 없습니다. 사용자 메시지에 제약이 없으면 일반적인 상기 문장이 가리킬 대상도 없기 때문입니다.

| 유도법 | 사용자 메시지 | 추론 시작 부분 |
|---|---|---|
| User Prompt | 과제 + 제약 | 모델이 바로 생성 |
| Constraint Prefill | 과제 | 제약을 명시한 자기 지시를 미리 제공 |
| User Prompt + Constraint Prefill | 과제 + 제약 | 구체적 자기 지시를 미리 제공 |
| User Prompt + Generic Prefill | 과제 + 제약 | 일반적 상기 문장을 미리 제공 |
| Constraint Bootstrap | 과제 + 제약 + 구체적 자기 지시를 쓰라는 요청 | 모델이 자기 지시부터 생성 |
| Generic Bootstrap | 과제 + 제약 + 일반적 상기 문장을 쓰라는 요청 | 모델이 상기 문장부터 생성 |

5. **2.4 Metrics — 완전 준수와 부분 준수**: Binary controllability는 해당 CoT 전체가 제약을 지켰는지 봅니다. 99%가 대문자여도 소문자가 하나 있으면 완전 준수는 실패할 수 있습니다. Soft metric은 대소문자 비율·단어 사이 삽입 비율·지정 단어로 끝나는 문장 비율 등을 따로 측정합니다. 단어 억제에서는 1,000단어당 금지 단어 수로 평가하므로 **낮을수록 좋습니다**. 시작·끝 문장 조건은 각각 50점인 경계 점수를 사용합니다. 질문 무시는 이와 같은 soft metric을 두지 않습니다.
6. **Echo rate의 별도 의미**: 요청한 자기 지시로 추론이 시작하는지 확인하되, 기본 echo는 대소문자와 공백을 정규화합니다. 그러므로 echo 성공과 문자 그대로의 복사 성공도 서로 다를 수 있습니다.

**챕터의 핵심 기여**: ‘형식을 잘 따른다’는 인상을 입력 경로·완전 준수·부분 준수·자기 지시 재현이라는 구분 가능한 측정치로 나눕니다.

**다음 챕터로의 연결**: 이 동일한 평가 틀을 모델별·출력별·턴별 조건으로 확장합니다. [2절, PDF 2–4쪽; Table 8, PDF 12쪽](https://arxiv.org/pdf/2610.23257v1#page=3)

마지막으로 generic 자기 지시를 분석합니다. 모델 평균 준수율은 기준 2.5%에서 Generic Prefill 12.1%, Generic Bootstrap 10.6%로 높아집니다. 이는 각각 구체적 자기 지시로 얻는 증가분의 76%·56%에 해당한다고 저자는 보고합니다. 단순히 같은 표면 형식을 앞에 보여준 효과만으로 결과 전체를 설명하기 어렵게 만드는 비교입니다. GPT-OSS의 상대적 저항성과 길이·정확도 분석은 부록 B·D에서 다룹니다.

#### 3.2 CoT vs. Output Controllability — 생각의 표현과 답변의 표현은 같지 않습니다

질문 무시를 제외한 각 제약에 QA 100문제를 사용하며, GPQA·HLE·MMLU-Pro를 균형 있게 구성합니다. 제약을 CoT에만, 출력에만, 양쪽에 함께 적용합니다. CoT 조건은 User Prompt + Constraint Prefill을 사용합니다. 답만 내놓게 되는 것을 피하려고 주 실험의 정답 형식 문장은 빼고, 출력 제약 조건에는 답과 설명을 요청합니다. 따라서 이 표의 수치를 주 실험 전체 평균과 직접 이어 붙이면 안 됩니다.

원문 Table 3의 평균은 다음과 같습니다.

| 모델 | CoT에만 제약을 둔 CoT 준수율 | 출력에만 제약을 둔 출력 준수율 |
|---|---:|---:|
| DeepSeek-R1 | 31.7% | 64.3% |
| Qwen3-14B | 18.4% | 47.3% |
| Qwen3-32B | 27.6% | 35.9% |
| GPT-OSS-20B | 11.5% | 50.0% |
| GPT-OSS-120B | 6.8% | 64.7% |

모든 모델에서 출력이 더 잘 제어되지만, 두 능력의 관련성은 모델군마다 다릅니다. DeepSeek-R1·Qwen3는 제약별 Pearson 상관 $`r=0.52`$, $`p=0.009`$, 질문별 이진 결과의 $`\phi=0.34`$, $`p<10^{-60}`$를 보입니다. GPT-OSS는 질문별 관계가 약하고($`\phi=0.12`$, $`p<10^{-5}`$), 제약별 관계는 통계적으로 유의하지 않습니다($`r=0.36`$, $`p=0.18`$). 상관은 두 능력이 같은 메커니즘이라는 증거와 동의어가 아닙니다.

이어 Table 4의 공동 제약을 비교합니다. DeepSeek-R1·Qwen3는 CoT 준수율을 대체로 유지하면서 출력 준수율도 유지하거나 높입니다. DeepSeek-R1의 출력 준수율은 64.3%에서 74.9%가 됩니다. 반대로 GPT-OSS-120B는 CoT 6.8%→2.5%, 출력 64.7%→57.9%로 낮아집니다. 저자는 공동 제약 효과에 McNemar 검정을 사용하며, DeepSeek-R1·Qwen3-32B의 출력 개선에는 $`p<10^{-4}`$를 보고합니다. 서로 다른 모델군을 하나의 ‘추론은 답변과 같다’는 설명으로 묶기 어렵다는 결과입니다.

#### 3.3 Closed Models — bootstrap과 prefill 접근 권한을 분리합니다

Reasoning 채널을 외부에서 미리 채울 수 없는 모델에도 bootstrap은 사용자 메시지를 통해 적용할 수 있습니다. QA 900개 하위 표본에서 Claude 3.7 Sonnet은 36.3%→43.3%, Claude Sonnet 4.6은 17.4%→24.2%로 준수율이 높아집니다. 자기 지시의 echo는 각각 97.6%·97.8%입니다. **98%의 echo를 98%의 제약 준수로 해석해서는 안 됩니다.**

관측 범위에도 차이가 있습니다. 원문 각주에 따르면 3.7 Sonnet은 전체 reasoning을 반환하지만, Sonnet 4.6은 reasoning 요약을 반환합니다. 이 실험의 제어 평가는 연구자가 관측할 수 있었던 텍스트에 근거하며, 요약과 원래 전체 추론이 동일하다고 보장하지 않습니다. 부록 E는 Sonnet 4.6의 `meow` bootstrap에서 유효 응답이 부족하여 해당 제약을 전체 점수에서 제외했다고 명시합니다.

#### 3.4 Multi-turn Bootstrap — 첫 턴에서 얻은 제어는 유지될까요?

주 실험은 첫 assistant 턴의 시작에만 자기 지시를 제공합니다. SWE-bench처럼 도구 사용과 관찰이 반복되면, 후속 턴에서 자기 지시 echo와 제약 준수가 빠르게 줄어듭니다. 저자는 Qwen3-32B에 매 턴 자기 지시로 시작하도록 요청하는 다중 턴 bootstrap을 적용합니다.

![SWE-bench에서 첫 턴 bootstrap과 매 턴 bootstrap의 자기 지시 echo 유지율]({{ '/img/reviews/2026/self-instructed-cot-review/figure-04-multiturn.png' | relative_url }})

*원문 Figure 4, PDF 7쪽. 축·범례·오차막대를 포함한 원본 그래프 크롭, 내용 수정 없음, CC BY 4.0. [원문](https://arxiv.org/pdf/2610.23257v1#page=7).*

후속 턴 echo는 기존 26–44%와 달리 82–95%로 유지됩니다. 그러나 전체 CoT의 완전 준수율 증가는 9.7%→12.8%입니다. 자기 지시의 유지와 전체 추론의 완전 준수가 얼마나 다른 지표인지 다시 드러납니다.

Table 6에서 `safe` 문장 종결은 완전 준수 18.0%→27.5%, 소문자는 9.5%→25.5%로 개선됩니다. 단어 억제에서는 자기 지시가 반복되는 루프가 발생하고, 자기 지시 안의 금지 단어가 다시 출현해 단어 빈도 점수가 나빠집니다. 여러 단어 억제의 금지 단어 수는 1,000단어당 52.9개에서 126.6개로 높아집니다. 따라서 지시를 더 자주 상기시키는 것이 모든 종류의 제약을 일관되게 돕는 것은 아닙니다.

#### 3.5 Monitor Evasion — 제약 준수가 감독 지표에도 영향을 줍니다

논문은 CoT Red-Handed의 통제된 프로그래밍 평가를 사용합니다. 모델은 본래 프로그래밍 과제와 별도 부수 과제를 수행하고, 모니터는 CoT와 최종 코드를 읽어 이를 탐지합니다. 이 글은 저자의 결과와 평가 조건을 분석하며, 실제 모니터 우회 실행이나 새로운 공격 절차를 제시하지 않습니다.

![사용자 지시와 자기 지시 조건의 모니터 탐지율 및 두 과제 동시 성공률]({{ '/img/reviews/2026/self-instructed-cot-review/table-07-monitor.png' | relative_url }})

### 📖 **Chapter 4: Related Work**

**챕터의 위치와 역할**: 새 결과를 기존 평가·개입·학습·감독 연구 사이에 위치시킵니다.

**저자의 서술 순서를 따른 상세 내용:**

1. **CoT controllability evaluations**: CoT-Control은 모니터 관점, ReasonIF는 활용성 관점에서 출발하지만, 사용자 메시지에 대소문자·문장 종결 등의 제약을 주고 낮은 준수율을 보고한다는 공통점이 있습니다. 이 연구는 CoT-Control의 과제와 채점기를 이어받아 제약 전달 방식을 바꿉니다.
2. **Reasoning interventions**: Thinking Intervention은 CoT 안의 지시로 최종 출력의 지시 준수와 안전성을 개선하는 선행 연구입니다. 추론 언어를 prefill로 지정한 연구도 있습니다. 이 논문의 차이는 CoT 자체를 여러 종류의 제약으로 평가하고, 어려운 QA와 도구·다중 턴 과제까지 확장한 데 있습니다.
3. **Training models to control their CoT**: Fine-tuning으로 제어 가능성을 높이는 연구와 달리, 여기서는 가중치를 추가로 최적화하지 않습니다. 따라서 이미 있는 능력을 얼마나 잘 유도했는지 측정하는 성격을 갖습니다. 학습 비용·미관측 제약으로의 일반화·CoT 직접 최적화가 감독에 미칠 수 있는 영향은 저자가 선행 연구와 함께 논의합니다.
4. **Evading monitors without controlling the CoT**: CoT를 일찍 끝내고 답변 공간에서 생각하도록 하는 방식은 CoT를 직접 제어하는 것과 다릅니다. 저자는 CoT를 남긴 상태에서 그 표현을 조절하는 결과를 구분해 제시합니다.

**챕터의 핵심 기여**: ‘추론 안에 지시를 넣는다’는 아이디어의 선행 맥락과, 이 논문이 새로 측정한 대상의 차이를 분명히 합니다.

**다음 챕터로의 연결**: 기존 평가와 함께 자기 지시 평가를 보고하자는 결론으로 이어집니다. [4절, PDF 8쪽](https://arxiv.org/pdf/2610.23257v1#page=8)

### 📖 **Chapter Limitations: Limitations**

**챕터의 위치와 역할**: 원문에서 번호 없이 제시한 세 한계를 그대로 구분합니다.

**저자의 서술 순서를 따른 상세 내용:**

1. **Text-level constraints**: 실험은 CoT가 무엇을 말하고 어떤 형식으로 쓰이는지를 제어합니다. 문제 해결 전략처럼 실제 추론 과정 자체도 같은 방식으로 제어되는지는 아직 검증하지 않았습니다.
2. **Reasoning prefill access and awareness**: prefill은 reasoning 채널 접근을 필요로 하고, 모델이 외부에서 채운 시작 문장임을 알아차릴 수도 있습니다. 저자는 bootstrap이 프롬프트 접근만 요구하고 자기 지시를 모델 자신이 생성하므로 이 두 문제를 피한다고 설명합니다. 실제 API 기능 지원 여부를 일반화하지는 않습니다.
3. **Capability, not propensity**: 명시적인 지시가 있을 때 제어와 탐지율 감소가 가능하다는 결과입니다. 모델이 그런 지시 없이 스스로 행동할지, 실제로 그러려 할지는 알 수 없습니다. 또한 모니터가 지시문을 보지 않는 실험 조건이며, 그 지시문까지 보는 모니터라면 탐지할 수 있다고 명시합니다.

**챕터의 핵심 기여**: 능력·자발적 성향·내부 추론·관측 가능한 텍스트를 구분합니다.

### 📖 **Chapter B: Extended Results**

**챕터의 위치와 역할**: 전체 평균이 숨기는 제약·데이터셋·길이·정답률의 차이를 살핍니다.

**저자의 서술 순서를 따른 상세 내용:**

1. **B.1 Results by Constraint and Method**: Table 10은 모델·제약·유도법의 전체 교차 결과를 제시합니다. 이진 셀의 SE는 최대 1.4%p라고 보고합니다. Qwen3-32B의 교대 대소문자는 User Prompt + Generic Prefill에서 단어 수준 83.0%이지만 완전 준수 2.9%에 그칩니다. 길고 복잡한 기록에서는 국소적 변화와 전체 무위반이 크게 벌어질 수 있습니다.
2. **B.2 Bootstrap Echo**: QA에서는 정규화 echo가 83–98%입니다. 예외적으로 DeepSeek-R1은 Agent 조건에서 자기 지시를 CoT가 아니라 답변에 쓰는 경우가 많습니다. BFCL 95%, SWE-bench 55%에서 이런 위치 이동이 나타나며, CoT 첫머리 echo는 두 벤치마크 모두 0%가 됩니다. 반대로 GPT-OSS는 문구를 거의 그대로 복사해도 이후 제약 준수는 낮을 수 있습니다. 자기 지시를 썼는지·어디에 썼는지·후속 생성이 지켰는지는 따로 측정해야 합니다.
3. **B.3 Results by Dataset**: BFCL·MMLU-Pro 평균 준수율은 각각 20.3%·14.6%, 추론 중앙값은 최대 632단어인 반면, SWE-bench는 준수율 1.2%, 길이는 최대 13,680단어입니다. 각 수치는 모델·방법을 평균한 데이터셋 비교이며, 특정 모델의 최고 성능 표와 다릅니다. 전체적으로 자기 지시 조건의 정답률 감소는 무제약 실행보다 1.4–1.6%p이며, 150개 막대 중 115개가 무제약 실행의 ±5%p 안에 있습니다.
4. **정확도 예외의 설명**: BFCL에서는 추론 제약이 도구 호출로 새어 나가 호출을 손상시키거나, Qwen3-14B가 bootstrap 조건에서 41–46%의 응답을 도구 호출 없이 끝내는 문제가 있습니다. Qwen3-32B의 무제약 QA 실행은 33%가 답을 추출할 수 없어 오답 처리되므로, 일부 제약 조건의 정답률이 최대 16.9%p 높아지는 현상도 보고합니다. 이를 곧바로 추론 능력 개선이라고 읽으면 안 됩니다.
5. **B.4 Controllability and Accuracy by CoT Length**: 답으로 끝난 CoT를 대상으로, 첫 자기 지시를 제외한 continuation의 단어 수를 분석합니다. 같은 모델·방법·데이터셋·제약 안에서도 길이가 두 배가 될 때 준수율이 3.1%p 낮아집니다. 이것은 관찰된 관계이며, 길이를 임의로 줄이면 성능이 그만큼 좋아진다는 인과 실험은 아닙니다.

### 📖 **Chapter D: GPT-OSS Resistance**

**챕터의 위치와 역할**: 자기 지시가 모든 모델에 동일하게 작동하지 않는 이유에 대한 가설을 분석합니다.

**저자의 서술 순서를 따른 상세 내용:**

1. **관찰의 출발점**: GPT-OSS는 자기 지시로 평균 점수가 높아지지만, Constraint Prefill 단독은 User Prompt보다 낮습니다. 개선도 주로 단어 억제 쪽에서 나타나고 문체 제약은 어렵습니다.
2. **Perplexity 비교 설계**: 모델별 무제약 QA CoT 1,000개를 뽑아 기계적으로 변환할 수 있는 여섯 제약에 맞춘 텍스트를 만듭니다. 두 단어 억제 조건은 User Prompt + Constraint Prefill에서 실제로 준수한 CoT를 사용합니다. 프롬프트 없이 CoT만 넣고, 각 모델 자신의 가중치가 부여하는 평균 perplexity를 무제약 CoT와 비교합니다. Perplexity는 이 문맥에서 해당 모델에게 그 텍스트가 얼마나 자연스러운지를 살피는 지표이며, 정답률이 아닙니다.
3. **관측과 해석의 경계**: Qwen3의 준수 텍스트/무제약 텍스트 perplexity 비율 평균은 1.11배·1.07배인 반면 GPT-OSS-20B·120B는 80배·2.39배입니다. 20B의 교대 대소문자 비율 625배는 소수의 극단적 CoT가 이끈 값이라고 저자가 명시합니다. 이 결과는 GPT-OSS의 추론 분포에서 그런 문체가 낯설다는 해석을 지지하지만, 학습 데이터의 실제 구성을 직접 관찰한 인과적 증명은 아닙니다. 저자가 제시하는 합성 추론 자료 중심 학습 가능성은 가설로 읽어야 합니다.

**챕터의 핵심 기여**: 제약 제어의 어려움을 일반적인 무능력으로 설명하는 대신, 모델별 추론 텍스트 분포 차이와 연결합니다.

**다음 챕터로의 연결**: 부록 E는 별도의 폐쇄형 모델에서 같은 지표가 어떻게 나타나는지 세분화합니다. [Appendix D·Table 15, PDF 18쪽](https://arxiv.org/pdf/2610.23257v1#page=18)

## 실험 결과 심층 분석

**첫째, 유도 방식은 능력 평가의 일부입니다.** 다섯 공개 모델 모두 기준 User Prompt보다 높은 최고 준수율을 보입니다. 다만 최고 방법은 모델별로 다르고, 제약별 반응도 다릅니다. 이 결과는 ‘전에는 못 하던 추론 능력이 생겼다’보다 ‘기존 능력을 관찰하는 방법을 바꾸면 측정값이 달라진다’는 주장에 더 직접적인 근거를 제공합니다.

**둘째, 지표를 한 숫자로 합치지 않아야 합니다.** Echo는 자기 지시를 쓴 비율, binary controllability는 continuation의 완전 준수, soft metric은 국소적 제약 충족 정도, accuracy는 원래 과제의 정답률입니다. Qwen3-14B의 `meow` 96.1%·완전 준수 38.7%, 다중 턴 echo 82–95%·전체 준수 12.8%가 이 차이를 잘 보여줍니다. 활용 목적에 따라 어느 지표가 필요한지를 먼저 정해야 합니다.

**셋째, 높은 제어와 높은 정답률은 따로 검증해야 합니다.** 전체적으로 정확도 손실이 작다는 결과와, 문구 ablation의 Qwen3-32B에서 제어가 높아지면서 정답률이 낮아진 결과가 동시에 존재합니다. BFCL의 도구 호출 손상과 미응답도 저자가 보고한 실패 양상입니다. 평균 정답률이 거의 같다고 해서 모든 호출 경로가 안정적이라는 뜻은 아닙니다.

**넷째, 통계적 근거는 결과별로 다릅니다.** 주 실험은 셀 단위 Bernoulli 가정의 SE를 제공하고, Figure 8은 95% 신뢰구간을 표시합니다. CoT–출력 관계는 상관계수와 p값, 공동 제약은 McNemar 검정, 모니터 비교는 층화 paired bootstrap을 사용합니다. 주 실험의 모든 막대쌍에 대한 다중 비교 보정 p값이나 반복 실행 seed별 분산은 논문에 보고되지 않았습니다. 따라서 모든 관측 차이를 동일한 수준의 유의한 개선으로 부르지 않습니다.

**다섯째, 감독 실험은 조건부 탐지율입니다.** 성공한 부수 과제 집합이 조건마다 달라지며 모니터는 지시문을 보지 않습니다. 이 조건에서 탐지율이 낮아졌다는 결과는 중요하지만, 사용자의 전체 입력까지 보는 모든 감독 시스템의 성능이나 실제 모델의 자발적 의도를 직접 측정하지는 않습니다. 이는 원문의 capability-not-propensity 한계와 정확히 연결됩니다.

## 기술적 함의와 응용

논문이 직접 제안하는 활용 방향은 추가 학습 없이 CoT의 언어·형식·구조에 대한 요구를 더 잘 유도하는 것입니다. 동시에 평가에서는 사용자 지시와 자기 지시 조건을 나란히 보고, 모니터를 시험할 때에도 더 강한 유도 조건을 고려하라고 권고합니다. 원문에 공개된 프롬프트·chat template·샘플링·채점법은 이러한 비교를 이해하는 데 필요한 재현 자료이지만, 이 리뷰에서 모델 실행이나 결과 재현을 수행한 것은 아닙니다.

**리뷰어 관점에서 데이터과학 실무와 연결되는 지점**은 평가 대상과 관측 지표를 분리하는 습관입니다. 최종 답변의 JSON 형식을 잘 지키는 모델이 CoT의 표현 제약도 잘 지키는 것은 아니며, 첫 턴에서 지켰다고 긴 도구 실행 전체에서 유지되는 것도 아닙니다. 또한 더 잘 드러난 텍스트 제어 능력은 CoT가 내부 계산의 충실한 기록임을 보증하지 않습니다.

이 연구의 결론은 추론을 완벽하게 통제하는 만능 프롬프트가 있다는 것이 아닙니다. **같은 모델의 제어 가능성을 어느 위치의 지시로, 어떤 continuation과 분모에 대해 측정했는가**가 활용성과 감독에 관한 판단을 바꾼다는 것입니다. 자기 지시가 드러낸 능력을 정확히 측정하는 일과, 그 능력이 안전하게 사용되는지 판단하는 일은 함께 다뤄야 합니다.
