## 논문 개요와 전체 구조

AI 에이전트가 지난번에 배운 내용을 다음 작업에서 활용하려면 무엇을 남겨야 할까요? 코딩 작업에는 저장소 구조와 명령 기록이 유용할 수 있지만, 매출 예측에는 숫자와 시간에 따른 변화가 더 중요할 수 있습니다. 두 경험을 하나의 긴 대화 기록에 넣는다고 필요한 지식이 저절로 정리되지는 않습니다.

FAIR at Meta의 Michael Philip 등 여섯 저자가 쓴 **Routed Continual Learning**은 기억의 내용을 요약하는 데서 한 걸음 앞의 선택을 다룹니다. 새 작업을 받으면 **어떤 기억 방식을 쓸지, 어느 작업들과 기억을 공유할지**를 함께 결정합니다. 여기서 지속 학습은 모델 가중치를 계속 훈련한다는 뜻이 아닙니다. 실행 사이에 남긴 상태를 골라 읽고 갱신하며, 그 결과를 에이전트의 입력 문맥에 넣습니다.

## 핵심 기여와 혁신성

기억을 오래 남기는 것과 적절하게 공유하는 것은 다른 문제입니다. 모든 작업의 실행 기록을 한곳에 쌓으면 정확한 세부 정보는 남지만 비용과 무관한 문맥이 늘어납니다. 하나의 요약 방식으로 통일하면 간결해지는 대신 다음 작업에서 필요할 정보를 버릴 수 있습니다. 이 논문은 모든 작업에 같은 표현을 강요하지 않고, 재사용할 정보의 성질에 따라 기억 방식을 선택합니다.

선택은 두 축입니다. **기억 시스템**은 원문 기록, 추상화한 전략, 통계적 수치 상태처럼 무엇을 보존할지 정합니다. **클러스터**는 그 기억을 어느 문제들이 함께 읽고 갱신할지 정합니다. 같은 기억 시스템을 쓰더라도 서로 다른 저장소나 상대방의 경험을 별도 클러스터로 나눌 수 있습니다. 방식 선택과 공유 범위를 한 번에 라우팅하는 것이 중심 설계입니다.

Context Memory Adapter는 이 선택을 기존 에이전트에 연결합니다. 에이전트의 도구나 최종 응답 형식을 바꾸지 않고, 실행 전에 선택한 기억을 문맥에 넣고 실행 뒤 그 상태를 갱신합니다. 실험에서도 전체 기록 공유, 기록의 클러스터 분리, 기억 방식 선택을 단계별로 추가해 각각의 효과를 구분합니다. 다만 새로운 기억 알고리즘을 자유롭게 합성하는 실험은 아닙니다. 선택 가능한 다섯 구현과 설정 범위는 평가 전에 고정돼 있습니다.

## 기술적 세부사항

여기서 **인스턴스(instance)**는 개별 문제 하나, **소스 과제(source task)**는 같은 종류 문제의 순서 있는 묶음입니다. 여러 과제의 문제를 섞되, 각 과제 내부의 발생 순서는 유지합니다. 에이전트는 현재 문제와 도구의 정상적인 피드백을 보지만, 평가용 과제 라벨이나 숨겨진 보상은 보지 못합니다.

클러스터가 선택되면 기억 시스템은 상태를 읽어 문맥을 만들고, 실행 궤적으로 상태를 갱신합니다. 원문 3절의 관계를 옮기면 다음과 같습니다.

```math
\begin{aligned}
z_t&=\mathtt{read}_m(S_{c,t},x_t;\theta_c),\\
S_{c,t+1}&=\mathtt{update}_m(S_{c,t},\tau_t;\theta_c).
\end{aligned}
```

$`x_t`$는 현재 문제, $`S_{c,t}`$는 클러스터 c의 상태, $`m`$은 그 클러스터의 기억 방식입니다. $`\theta_c`$는 입력 필드와 기억 형식의 대응 등을 정한 설정이며, $`z_t`$는 에이전트에게 추가되는 문맥입니다. $`\tau_t`$는 정상 실행에서 드러난 프롬프트·행동·도구 출력·피드백의 궤적입니다. 선택하지 않은 클러스터는 바뀌지 않습니다.

핵심 절차를 설명용 의사코드로 적으면 다음과 같습니다. 논문의 구현을 실행한 결과나 원본 코드 인용은 아닙니다.

```text
입력: 현재 문제와 응답 스키마, 고정 기억 방식 목록, 클러스터 요약
라우터가 기존 클러스터 재사용 또는 새 클러스터 생성을 선택
선택한 클러스터의 기억을 읽어 원래 문제 옆에 보조 문맥 삽입
기존 에이전트가 원래 도구와 응답 형식으로 문제 수행
공개된 실행 궤적으로 선택한 클러스터만 갱신
출력: 에이전트의 응답, 다음 문제에 남길 클러스터 상태
```

평가 지표의 이름도 구분해야 합니다. **normalized reward**는 CL-Bench가 발표한 외부 기준을 0으로 놓는 주 지표입니다. **stateless-reference gain**은 이번 실험에서 같은 모델이 기억 없이 수행한 점수를 0으로 놓는 보조 지표입니다. 둘 다 일곱 과제를 같은 비중으로 평균하지만 기준점과 분모가 다릅니다. 398개 문제를 개수대로 가중 평균한 정확도도 아닙니다.

## 챕터별 상세 리뷰

### 📖 **Chapter 1: Introduction**

도입부는 여러 에이전트가 비슷한 일을 할 때 경험을 공유하면 얻을 이점에서 출발합니다. 같은 오류를 반복하지 않고, 필요한 정보나 방법을 다시 찾는 비용을 줄일 수 있습니다. 저자들은 보안 평가에서 독립 에이전트들이 의도치 않은 공유 공간으로 발견을 전달한 사례를 동기로 소개합니다. 이 리뷰가 그 외부 평가를 독립적으로 검증한 것은 아니며, 논문은 이런 공유를 우연에 맡기지 않고 설계 대상으로 삼습니다.

기억에 남길 정보는 작업에 따라 다릅니다. 저장소 구조, 도구 사용 사례, 근거가 있는 사실, 시계열 추정치는 같은 형태로 다루기 어렵습니다. 저자들이 요구하는 두 특성은 기존 에이전트의 협조 없이 입력 문맥을 보강하는 **투명한 연결**과, 적절한 기억 방식·상태를 고르는 **라우팅**입니다.

원문은 CL-Bench가 여섯 과제를 각각 분리해 평가했을 때 단순 ICL이 강했다고 설명합니다. ICL은 이전 문제와 답·피드백을 문맥에 계속 넣는 방식입니다. 그러나 코딩과 포커, 통계 추정 문제가 번갈아 들어오면 하나의 기록에 서로 관련 없는 정보가 섞입니다. 따라서 같은 과제끼리 평가한 결과를 혼합 업무에 그대로 적용할 수 없다는 문제를 제기합니다.

이를 시험하기 위해 여섯 CL-Bench 과제 301개에 은행 고객 서비스 97개를 더합니다. 새 문제마다 라우터가 기존 상태를 재사용하거나 새로운 상태를 만들며, 새 클러스터에는 기억 방식을 지정합니다. 도입부의 기여는 경험 표현과 공유 범위를 함께 결정하는 문제 정의, 그 선택을 실행하는 구조, 네 모델·다섯 반복에서의 보상–비용 비교입니다. 다음 절은 이 설계가 기존 지속 학습·문맥 보강과 어떻게 이어지는지 짚습니다.

### 📖 **Chapter 2: Related Work**

**Analysis of algorithms and learning theory.** 첫 소주제는 한 번의 문제를 잘 푸는 시스템과 관련 문제의 연속을 잘 처리하는 시스템의 차이입니다. 분할 상환 분석은 일련의 연산 전체 비용을, 자기 개선 알고리즘은 반복되는 데이터 분포를, 온라인 학습은 순차적으로 드러나는 정보에 대한 의사결정을 봅니다. 저자들은 상태를 보존해 반복 비용을 줄인다는 공통 관점을 연결합니다. 이 논문이 새로운 경쟁비 보장을 증명하는 것은 아닙니다.

**Prompt rewriting and context augmentation.** 이어 APE·GEPA의 프롬프트 최적화, Eevee의 라우터와 프롬프트 공동 최적화를 소개합니다. Routed CL은 평가 중 라이브러리 자체를 최적화하는 대신, 현재 문제에 사용할 고정된 구현과 상태를 고릅니다. Dynamic Cheatsheet와 ACE가 하나의 누적 문맥을 발전시키는 접근이라면, 여기서는 경험을 별도 클러스터로 나눠 관련 없는 작업이 같은 기록을 읽지 않도록 합니다.

**Memory systems.** 다음 비교 축은 무엇을 저장하는가입니다. MemGPT의 외부 메모리, Mem0의 사실 갱신, Reflexion·ExpeL·ReasoningBank의 교훈 추출, 워크플로·실행 스킬·잠재 표현 등 다양한 방식이 나옵니다. Routed CL은 이들 가운데 하나만 항상 옳다고 전제하지 않는 상위 구조입니다. 다만 평가에서는 모든 기존 시스템을 구현해 비교한 것이 아니라 정해진 다섯 방식만 사용했습니다.

**Standard harness hooks and rewriters.** 마지막으로 에이전트 프레임워크가 이미 제공하는 메시지 훅을 연결 지점으로 설명합니다. Context Memory Adapter는 이 위치에서 원래 에이전트의 코드를 바꾸기보다 기억을 입력에 덧붙입니다. 메시지를 검열하는 기능과 같은 것은 아니며, 목적은 과거 경험을 현재 작업에 공급하는 데 있습니다. 다음 3절은 이렇게 읽고 쓰는 상태를 수학적으로 정의합니다. [원문 2절](https://arxiv.org/html/2610.38796v1#S2)

### 📖 **Chapter 3: Problem Formulation**

**Heterogeneous continual streams.** 각 소스 과제에는 고유한 문제 순서가 있습니다. 전체 흐름은 이를 무작위로 섞되 과제 내부 순서를 유지합니다. t번째 문제를 수행할 때 아직 오지 않은 문제나 평가 결과를 이용할 수 없습니다. 정상 상호작용에서 드러난 행동·관찰·피드백은 궤적으로 남지만, 환경이 평가용으로 계산한 보상은 학습 시스템에 전달되지 않습니다.

**Continual-learning memory systems.** 기억 시스템은 상태에서 문맥을 읽는 연산과 실행 궤적으로 상태를 갱신하는 연산을 제공합니다. 라이브러리의 구현과 허용 설정 스키마는 평가 전에 고정됩니다. 에이전트가 새 파서 코드를 만들거나 숨겨진 답을 설정 안에 저장하는 자유로운 프로그램 합성과 다릅니다. 메모리는 에이전트 대신 환경에서 행동하지도, 에이전트 LLM의 파라미터를 고치지도 않습니다.

일부 방식은 과제의 응답 필드가 통계 모델의 어떤 역할에 해당하는지 연결해야 합니다. 예를 들어 어떤 열이 예측할 값인지, 어떤 열이 개체를 식별하는지 정하는 작업입니다. 이 대응은 클러스터별 어댑터 설정에 들어갑니다. 기억 시스템이 같아도 그 설정과 누적 상태는 클러스터마다 분리됩니다.

**Stateful routing.** 라우터는 문제와 기억 방식의 설명, 클러스터 요약을 보고 기존 클러스터를 재사용하거나 특정 방식의 새 클러스터를 만듭니다. 클러스터 설명은 생성 뒤 바뀌지 않으며, 이번 문제의 배정은 실행 도중에도 고정됩니다. 너무 넓게 묶으면 무관한 경험이 간섭하고, 지나치게 쪼개면 활용할 경험이 쌓이지 않습니다.

이로써 네 실험 조건의 차이가 정리됩니다. Stateless ICL은 문제 사이 상태가 없고, Global ICL은 전체 흐름에 하나의 ICL 기록을 둡니다. Routed ICL은 ICL 기록을 여러 클러스터로 나누고, Routed CL은 클러스터뿐 아니라 기억 방식도 선택합니다. 이 선택의 실제 구성 요소가 다음 절의 내용입니다.

### 📖 **Chapter 4: System Components**

**4.1 Router and Stateful Clusters.** 라우터는 문제마다 구조화된 출력의 LLM 호출 한 번을 사용합니다. 입력은 현재 프롬프트와 응답 스키마, 기억 방식 설명, 각 클러스터의 ID·기억 방식·고정 설명·완료 궤적 수입니다. 원시 궤적이나 내부 통계 상태를 직접 들여다보는 것은 아닙니다. 이전 라우팅 호출의 숨은 대화 상태도 받지 않습니다.

라우터는 이 평가에서 새로 학습되지 않습니다. 고정 프롬프트로 선택하며 소스 과제 라벨과 평가 보상도 받지 않습니다. 다만 현재 프롬프트에 드러난 구조는 볼 수 있습니다. 따라서 과제 라벨이 없다는 사실을 어떤 작업인지 추론할 단서조차 없다는 뜻으로 읽으면 안 됩니다.

**4.2 Frozen Memory-System Library.** 다섯 기억 방식은 세 표현 계열로 정리되지만, 라우터가 고르는 것은 다섯 개의 실제 시스템입니다. 계열을 먼저 선택하는 추가 단계는 없습니다. 라이브러리는 CL-Bench를 이용한 탐색 개발 중 골랐고 확인 평가 전에 고정했습니다.

| 기억 방식 | 남기는 상태 | 잘 맞는 관측 구조 |
| --- | --- | --- |
| ICL | 순서 있는 원래 실행 기록 | 정확한 사실·행동·피드백을 다시 볼 필요가 있을 때 |
| ReasoningBank(RB) | 성공·실패에서 추린 전략·예방 교훈 | 독립적인 문제들 사이에 절차를 재사용할 때 |
| Hierarchical Regression(HR) | 반복 수치 결과의 계층적 회귀 상태 | 일정한 식별 키를 가진 개체·패널의 값과 시간 |
| Hierarchical Discrete-Event State(HDE) | 시간 구간별 사건 미발생 확률 | 순서 있는 구간에서 단조롭게 줄어드는 확률 곡선 |
| Persistent-Entity State(PES) | 불확실한 개체 대응과 수치 추정 | 식별자가 고정되지 않은 잡음 있는 관측 묶음 |

원문 Table 2를 의미 중심으로 다시 쓴 표입니다. HR·HDE는 PyMC, PES는 River의 Bayesian linear regression을 사용합니다. 통계 라이브러리는 CL-Bench의 과제명·고유 필드·채점 규칙을 포함하지 않으며, 의미 연결은 어댑터와 추출 증거를 통해 들어갑니다.

ICL은 문맥 한도에서 오래된 메시지를 버리는 것 외에 원래 기록을 보존합니다. RB는 같은 모델이 실행의 성공·실패를 스스로 판단하고 최대 세 개의 기억 항목을 만듭니다. 다음 문제에서는 요청 의미가 가장 비슷한 과거 경험 하나를 찾아 그 경험의 기억들을 넣습니다. 이 RB 변형은 숨겨진 보상을 사용하지 않고 고정된 로컬 임베딩을 사용하며, 원래 RB의 테스트 시 확장 기능은 사용하지 않습니다.

**4.3 Context Memory Adapter.** 어댑터는 선택 상태를 읽어 첫 에이전트 턴 전에 제한된 길이의 조언을 넣습니다. 원래 문제, 도구, 응답 스키마와 최종 답을 제출하는 에이전트는 유지됩니다. 설정 가능한 기억 방식에는 관찰 가능한 첫 실행을 바탕으로 필드 대응을 정하는 과정도 있습니다.

이 보조 문맥은 실행 중 대화 기록에 남습니다. 갱신은 이번에 선택된 클러스터의 궤적만 이용합니다. 어댑터가 환경에서 답을 제출하거나 숨은 테스트·보상에 접근하지 않는 경계를 지켜야 기억의 효과와 과제 수행 자체를 구분할 수 있습니다. 다음 절은 이 구조를 비교할 평가 조건을 고정합니다. [원문 4절](https://arxiv.org/html/2610.38796v1#S4)

### 📖 **Chapter 5: Experiments**

**Benchmark and heterogeneous stream.** CL-Bench의 코드 적응·코호트 연구·DB 탐색·포커·매출 예측·스펙트럼 감시 301개와 은행 고객 서비스 97개를 섞습니다. 각 반복은 서로 다른 무작위 혼합 순서를 쓰지만, 한 반복 안에서는 모든 비교 방법이 같은 흐름을 받습니다. 각 원천 과제의 내부 순서도 유지합니다.

**Compared systems.** 네 단계 조건은 같은 에이전트, 도구·응답 인터페이스, 행동 예산, 모델 제한과 문제 순서를 사용합니다. ICL의 문맥 예산은 100K토큰입니다. Global ICL은 전체 흐름 하나에, 라우팅 조건은 각 클러스터에 독립적으로 이 한도를 적용합니다. 따라서 총 보유 가능 문맥의 의미까지 완전히 같은 조건은 아니며, 실제 사용 비용을 함께 측정합니다.

별도의 RB 비교는 Global RB와 Routed RB를 **세 번의 짝지은 반복**으로 평가합니다. 주 비교의 다섯 반복과 같은 표본으로 섞지 않습니다. Ground-truth assignment는 소스 과제 정체성을 알고 탐색 개발에서 정한 기억 방식·분할을 적용하는 진단 조건입니다. 숨은 과제 라벨을 받지 않는 주 방법과 정보 조건이 다르고, 최적 정책이나 성능 상한으로 정의된 것도 아닙니다.

**Models and repetitions.** 모델은 Claude Opus 4.7, Claude Opus 5, GPT-5.6 Sol, Gemini 3.7 Flash입니다. 각 조건에서 에이전트뿐 아니라 라우터·설정기·추출기·RB 판단기 등 모델을 쓰는 역할은 같은 평가 모델을 사용합니다. 은행 업무의 사용자 시뮬레이터와 평가기는 모든 조건이 공유하는 벤치마크 구성 요소입니다.

각 모델–조건을 다섯 번 전체 실행합니다. 뒤의 문제는 앞의 경험에 영향을 받으므로 독립 반복의 단위는 문제 398개 각각이 아니라 **전체 rollout**입니다. 방법 차이도 같은 순서를 사용한 다섯 쌍으로 요약합니다.

**Evaluation protocol.** 라우터·프롬프트·통계 기본값·기억 구현과 진단 배정은 확인 평가 전에 고정합니다. 매출 예측에서는 문제마다 쓰기 작업 공간을 초기화하고, 코드 적응에서는 기본 커밋만 보이는 스냅샷을 제공하며 회귀 테스트를 평가용으로 분리합니다. 이 변경은 모든 방법에 공통이지만 역사적 CL-Bench 점수와 엄밀히 같은 실행 프로토콜은 아닙니다.

**Metrics.** 주 지표는 normalized reward입니다. CL-Bench 여섯 과제는 발표된 외부 stateless GPT-5.4 점수를 기준으로 보상 척도를 바꾸고, 은행 과제는 원래 0–1 보상을 사용합니다. 일곱 과제의 비중은 같습니다. 보조 지표는 같은 모델·같은 순서의 Stateless ICL과 비교한 이득입니다. 비용에는 라우팅과 기억 관리까지 **모든 모델 호출**을 포함하며, 고정된 날짜의 공개 단가로 토큰 캐시 읽기·쓰기 등을 나눠 계산합니다. 현재 API 요금이나 벽시계 실행 시간의 측정치는 아닙니다. [원문 5절](https://arxiv.org/html/2610.38796v1#S5)

### 📖 **Chapter 6: Results and Analysis**

**Global ICL loses its advantage under heterogeneous interleaving.** 소스 과제를 분리했을 때와 달리, 혼합 흐름에서 하나의 공유 기록은 이득이 작았습니다. 네 모델의 평균 stateless-reference gain은 Global ICL 0.015, Routed ICL 0.222, Routed CL 0.280입니다. 이것은 같은 모델의 기억 없는 조건을 기준으로 한 보조 척도입니다. 아래 주 지표 표의 값과 이름 없이 바꿔 쓸 수 없습니다.

**Clustering helps ICL but does not consistently help ReasoningBank.** ICL 기록을 나누면 모델별 normalized reward가 0.117–0.241점 높아집니다. RB에서는 클러스터를 나눈 효과가 일관되지 않고 비용이 8–29% 증가합니다. 저자들은 RB가 이미 요청 유사도로 기억을 선택해 검색한다는 구조를 가능한 설명으로 듭니다. 모든 기억 시스템에 같은 분할 전략이 이득이라는 결과는 아닙니다.

**Memory-system selection adds task-specific gains.** 기억 방식 선택까지 추가하면 Routed ICL보다 0.002–0.076점 더 높아집니다. Gemini는 평균 차이가 0.002로 작고 다섯 반복 중 네 번 양수입니다. GPT-5.6 Sol과 Opus 5는 다섯 번 모두 양수이며, 세부 차이는 부록 Table 5에 있습니다. 과제별로는 코호트·은행에서 모든 모델, 스펙트럼에서 네 모델 중 셋이 좋아졌습니다.

| 모델 | Stateless ICL | Global ICL | Routed ICL | Routed CL |
| --- | --- | --- | --- | --- |
| Gemini 3.7 Flash | −0.055 | −0.030 | 0.211 | 0.213 |
| GPT-5.6 Sol | 0.130 | 0.168 | 0.387 | 0.464 |
| Opus 4.7 | 0.060 | 0.092 | 0.209 | 0.243 |
| Opus 5 | 0.178 | 0.169 | 0.340 | 0.401 |

원문 [Table 1](https://arxiv.org/html/2610.38796v1#S1.T1)의 다섯 반복 평균 normalized reward입니다. 음수는 외부 stateless 기준보다 낮다는 뜻입니다. 원문이 함께 제공한 최소–최대 범위와 짝지은 차이는 부록 C에서 이어 설명합니다.

**Routed CL improves the reward–cost trade-off.** Routed CL은 Global ICL보다 보상은 높고 추정 비용은 65–72% 낮습니다. Routed ICL보다도 세 모델에서는 비용이 25–33% 낮지만, **Opus 4.7에서는 약 5% 비싸고 보상은 0.034점 높습니다.** 같은 보상 증가를 얻는 대가가 모델마다 다릅니다.

이 네 단계 조건에서 Routed CL은 각 모델의 경험적 보상–비용 Pareto 전선에 놓입니다. 이는 평가한 조건 사이에 더 싼 비용으로 더 높은 보상을 주는 대안이 없다는 뜻입니다. 모든 기억 방식과 모든 배포에서 최적이라는 보장은 아닙니다. RB와 비교하면 Global RB보다 0.189–0.358점 높은 보상에 비용은 31–44% 더 듭니다. RB의 저비용 지점도 함께 봐야 합니다.

**Routing leaves model-dependent headroom.** 과제 정체성을 아는 진단 배정을 쓰면 Opus 5·GPT의 차이는 각각 0.008·0.014점이지만, Opus 4.7·Gemini는 0.069·0.071점입니다. 20개 모델–반복 조합에서 소스 과제 단위 기억 방식 일치는 86%, 클러스터 분할 일치는 91%, 둘 다 일치는 79%였습니다. 이는 진단 배정과의 일치율이지 실제 정답을 알고 측정한 범용 라우팅 정확도가 아닙니다. 다음 절은 이를 바탕으로 결론과 평가하지 않은 배포 조건을 정리합니다. [원문 6절](https://arxiv.org/html/2610.38796v1#S6)

### 📖 **Chapter 7: Conclusion and Future Work**

저자들은 이질적인 업무 사이의 지속 학습을 경험의 표현 방식과 공유 범위를 함께 고르는 문제로 정리합니다. 이번 흐름에서 Routed CL은 네 모델 모두 Global ICL·Routed ICL보다 높은 평균 보상을 보이고 Global ICL보다 비용을 크게 줄였습니다. 모든 경험을 한 기록에 넣는 방식의 이득이 작아진 조건을 보여 준 것이 결론의 핵심입니다.

**A.6 Metric Definitions.** CL-Bench 과제 d에서 방법 M의 평균 원래 보상을 다음처럼 바꿉니다.

```math
R_d(M)=\frac{\bar r_d(M)-r_d^{\mathrm{ext}}}
                 {r_d^{\max}-r_d^{\mathrm{ext}}}.
```

$`r_d^{\mathrm{ext}}`$는 외부 stateless GPT-5.4 기준이고 최대 보상까지 남은 간격이 분모입니다. 은행 과제는 원래 0–1 보상을 그대로 사용합니다. 별도의 stateless-reference gain은 같은 모델·같은 seed의 기억 없는 조건 B를 기준으로 합니다.

```math
G_d(M)=\frac{\bar r_d(M)-\bar r_d(B)}
                 {r_d^{\max}-\bar r_d(B)}.
```

여기서 $`\bar r_d(B)`$는 이번 실험의 짝지은 Stateless ICL 보상입니다. 각 지표는 과제별 계산 뒤 일곱 과제를 균등 평균합니다. 주 결과의 0.15–0.30점 개선을 Global ICL 보상 대비 상대 향상률 15–30%라고 바꾸면 분모가 달라집니다.

### 📖 **Chapter Appendix B: Additional Method Details**

**B.1 Adapter Validation and Evidence Repair.** ICL에는 별도 설정이 없지만 RB와 수치 기억에는 필드 대응이 필요합니다. 설정 가능한 클러스터의 첫 문제는 원래 프롬프트 그대로 풀고, 완료된 궤적을 warm-up 사례로 남깁니다. 그 클러스터가 처음 재사용될 때 과거 궤적과 현재 문제·응답 스키마로 설정합니다. 첫 문제를 보기도 전에 과제별 최적 설정이 준비돼 있는 것은 아닙니다.

수치 방식은 새 런타임에서 warm-up을 다시 읽고 현재 문제를 준비하며 상태·필드 대응을 검증합니다. 오류가 있으면 결정적인 검증 메시지로 전체 설정을 **한 번 수정**할 수 있습니다. 두 번째도 실패하면 검증하지 않은 설정을 받아들이지 않고 설정을 종료합니다. 통과한 설정은 클러스터 수명 동안 고정됩니다.

이후 typed extractor는 현재 질의나 완료 궤적처럼 공개된 사건 하나를 정해진 레코드로 옮깁니다. 스키마·내부 일관성·숫자의 정확한 출처를 검증하고, 잘못된 묶음은 최대 한 번 수리합니다. 계속 실패하면 조용히 자르거나 수용하지 않고 실패를 알립니다. 추출기는 통계 모델을 적합하거나 개체를 연결하거나 답을 예측하지 않습니다.

**B.2 Numerical Memory-System Implementations.** HR은 안정적인 키·범주 요인·선택적 시간 변화를 가진 반복 수치를 계층 회귀로 모읍니다. 전체·키·요인·시간 항을 PyMC로 적합하고 새 관측이 오면 갱신합니다. 반복 지지가 생긴 추정은 잡음 추정치와 최근 관측을 포함한 간결한 예측으로 렌더링하며, 에이전트는 현재 환경에 따라 수정할 수 있습니다.

HDE는 순서 있는 구간의 조건부 hazard, 즉 그 구간에서 사건이 생길 가능성을 모델링합니다. 구간 기본값과 특징·개체·맥락 효과를 함께 추정한 뒤 사건 미발생 확률로 바꿔 유효한 단조 곡선을 만듭니다. PES는 일정하지 않은 크기의 관측 집합에서 불확실성을 고려해 개체를 대응시키고, 지속 ID 추정과 온라인 Bayesian 회귀를 갱신합니다. 관측값을 어떤 개체로 연결할지는 추출 LLM이 아니라 고정 런타임이 맡습니다. [원문 부록 B](https://arxiv.org/html/2610.38796v1#A2)

### 📖 **Chapter Appendix D: Prompts and Memory-System Descriptions**

부록 D는 방법을 정의한 고정 프롬프트와 출력 계약을 공개합니다. 다음은 원문 프롬프트 전문을 복제한 것이 아니라, 어떤 입력을 허용하고 어떤 출력을 요구하는지 순서대로 풀어쓴 설명입니다. 런타임 값의 자리표시자, 벤치마크 자체 프롬프트·응답 스키마와 공급자별 전송·재시도 메시지의 구분도 원문에 명시돼 있습니다.

**D.1 Router.** 라우터는 공급된 문제·클러스터 요약·기억 방식 선언만 사용합니다. 이름이나 후보 목록 순서 때문에 방식을 선호하지 말고, 공유 범위가 맞고 간섭 없이 도움이 될 때 기존 상태를 재사용하도록 지시합니다. 출력은 `kind`, `cluster_id`, `system_id`, `description` 네 필드를 항상 포함하고 적용되지 않는 필드는 null입니다. 기존 클러스터를 택하면 ID를, 새로 만들면 방식과 향후 공유 범위의 설명을 냅니다. 다섯 방식의 설명은 정확한 기록, 전략 교훈, 키가 있는 스칼라, 단조 확률 곡선, 잡음 있는 지속 개체라는 관측 구조를 구별합니다.

**D.2 Adapter Configuration.** D.2.1 공통 계약은 스키마가 허용하는 선택만 설정하고 파서 코드·답·숨은 보상·새 연산자를 만들지 않도록 제한합니다. D.2.2 RB 계약은 반복 포장 문구와 실제 요청 사이의 경계만 정합니다. 보인 프롬프트마다 정확히 한 번 나오는 구분자를 택하거나 적절할 때 null로 두며, 구체적 과제 사실·답·도구 이름을 규칙에 담지 않습니다.

D.2.3 HR 계약은 반복 수치의 의미 차원, 예측할 시점, 이미 공개된 실제 결과를 구별합니다. 목표 종류는 실수·양의 연속값·개수·확률 중에서, 시간 효과는 없음·선형 중에서 선택합니다. 수치 사전분포·추세·잡음·축소 상수는 설정 LLM이 주지 않습니다. D.2.4 HDE 계약은 구간 개수와 반복되는 범주 맥락 역할을 정하고, 개체 ID·단발 라벨을 집단 맥락으로 잘못 쓰지 않게 합니다. 실제 숫자와 타깃 답은 manifest에 넣지 않습니다.

D.2.5 PES 계약은 개체 정체성을 나타내는 안정적인 수치 좌표와 시간에 따라 흔들리는 값을 분리합니다. 관측의 폭·크기·불확실성 같은 스케일 기준과 그 해석을 선언하되, 실제 매칭 임계값·잡음 수준·지원 횟수 임계값은 런타임이 정합니다. 수치 방식 설정에 공급하는 완료 궤적에서는 최종 제출 값이 관측이 아닌 후보 답이므로 생략합니다. RB 설정에는 이전·현재 초기 프롬프트만 줍니다. 검증 실패 시 한 번의 완전한 수정 설정을 요청하는 계약으로 연결됩니다.

**D.3 Typed Evidence Extractors.** D.3.1 HR 추출기는 현재 시점과 모든 요청 예측 지점을 기록하지만, 이미 보인 실제 결과만 관측으로 복사합니다. 과거 예측·오류·점수·도구로 읽을 수도 있는 미공개 자료를 관측으로 취급하지 않습니다. D.3.2 HDE 추출기는 응답 필드의 의미 순서, 정확한 타깃 ID와 특징, 0부터 세는 근거 turn, 원문의 연속 발췌 위치와 확률·지원 가중치를 연결합니다. 실제 0과 1을 임의의 작은 양수나 바닥값으로 바꾸지 않습니다. 직접 측정과 적합·예측 값을 구분하고, 중복·모호한 행을 무조건 모두 넣지 않습니다.

D.3.3 PES 추출기는 공개된 관측 집합을 빠짐없이 의미 역할에 맞춰 복사합니다. 여러 사건 사이 개체를 연결하거나 단위를 변환하거나 지속 개체를 예측하지 않습니다. 이 세 추출 스키마에는 고정 구조·출처 검증이 적용되며, 실패하면 오류와 거절된 묶음을 보고 허용된 한 번의 수리를 요청합니다. 수치 연산과 해석 역할을 한 LLM 호출에 모두 맡기는 구조가 아닙니다.

**D.4 ReasoningBank Memory Formation.** D.4.1 자기 판단은 보인 요청과 실행 궤적만으로 성공·실패와 짧은 근거를 냅니다. 이는 평가기의 숨은 정답을 받은 라벨이 아닙니다. D.4.2 기억 추출은 성공이면 왜 성공했는지, 실패면 어떤 절차로 같은 실패를 피할지 검토해 최대 세 항목을 만듭니다. 항목은 `title`·`description`·`content`를 가지며, 중복·추상적 구호와 구체적인 과제 ID·숫자·쿼리를 피하고 재사용할 수 있는 절차를 남기도록 합니다.

**D.5 Actor-Facing Context Templates.** D.5.1 RB는 가장 비슷한 과거 경험 하나에서 얻은 기억 항목들을 넣고 관련 있을 때만 사용하도록 안내합니다. D.5.2 HR은 최근 실제 결과, 예측·불확실성과 지지 정보, 이미 결과가 드러난 예측의 잔차를 보여 주며 추정이 정답이나 제출이 아님을 명시합니다. D.5.3 HDE는 공개된 모집단·개체 측정, 지원 수와 정규 조건을 지키게 하고, 현재 자료의 선택 효과와 축적 증거를 구분합니다. D.5.4 PES는 후보 개체의 정체성·지지·관측 시점·현재 활성 상태·예측값을 보여 주되 중복이나 잡음일 수 있으므로 에이전트가 최종 응답을 만들도록 합니다. 네 템플릿 모두 기억을 최종 정답으로 강제하지 않고 보조 문맥으로 전달합니다. [원문 부록 D](https://arxiv.org/html/2610.38796v1#A4)

## 실험 결과 심층 분석

가장 큰 효과는 ICL 기록을 분리하는 단계에서 나옵니다. Table 1 기준 Global ICL→Routed CL의 평균 보상 차이는 모델별 약 0.151–0.296점이며, 그중 상당 부분은 Routed ICL에서도 얻습니다. 기억 방식의 선택이 더한 평균 이득은 모델별로 다르고, Gemini에서는 작습니다. 따라서 모든 개선을 통계 기억 시스템의 효과로 묶으면 단계별 비교의 의미가 사라집니다.

불확실성도 원문이 보고한 방식으로 읽어야 합니다. Table 1·4는 다섯 반복의 평균과 최소–최대, Table 5는 같은 seed로 짝지은 차이와 양수 횟수를 제공합니다. Figure 4 음영도 최소–최대입니다. 문제 398개는 서로 독립적인 반복 실행 398회가 아닙니다. 별도의 통계적 유의성 검정이나 신뢰구간은 논문에 보고되지 않았습니다. 모든 모델에서 평균이 높다는 관찰과 모든 차이가 통계적으로 유의하다는 주장은 다릅니다.

비용 절감의 기준도 중요합니다. Routed CL은 긴 전체 기록을 반복해서 읽는 Global ICL보다 저렴합니다. 그러나 기억 없는 실행이나 RB보다 항상 싼 구조는 아닙니다. 숫자 상태가 잘 맞는 과제에서는 압축된 예측을 제공할 수 있지만, 분할이 너무 넓거나 세밀해져도 비용과 이전 경험의 효용이 달라집니다. 이런 차이는 평균 보상과 전체 토큰만으로 설명되지 않아 과제별 비용 비율과 캐시 종류를 함께 제시한 점이 유용합니다.

재현성에서는 고정 프롬프트·스키마와 실행 프로토콜을 공개한 점, 모델을 쓰는 모든 역할의 비용을 포함한 점을 확인했습니다. 반대로 이 결과는 일곱 과제의 정해진 혼합·순차 실행과 평가 전 선택한 라이브러리에서 얻은 것입니다. 과거 CL-Bench 집계와 엄밀히 같은 수치 대결로 제시하거나, 분산 다중 모델 배포까지 입증한 결과로 확대해서는 안 됩니다.

## 기술적 함의와 응용

이 논문이 제안하는 설계 단위는 기억 저장소 하나보다 구체적입니다. 새 문제가 들어왔을 때 경험의 형태와 공유 대상을 함께 고르고, 원래 에이전트에게는 선택된 경험을 문맥으로 전달합니다. 코딩 기록을 그대로 다시 읽을 경우와 반복 수치에서 통계 상태를 추정할 경우를 같은 표현으로 통일할 필요가 없다는 관점입니다.

리뷰어의 해석으로는, 기억 시스템을 비교할 때 저장된 내용만 아니라 **누가 같은 상태를 읽고 갱신하는지**도 평가해야 한다는 점이 중요합니다. 주 실험은 이 선택이 보상과 비용을 바꾼다는 근거를 제공합니다. 동시에 RB의 분할 효과가 일관되지 않았고, 일부 모델의 추가 이득은 작았다는 결과도 남습니다. Routed CL은 하나의 기억 방식이 모든 업무를 대신한다는 결론보다, 업무가 섞였을 때 기억의 표현과 공유 범위를 따로 설계해야 한다는 결론을 뒷받침합니다.
